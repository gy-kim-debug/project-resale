# 화면 토대

2026-10-19. [사용자 확정 설계](design/README.md)를 바탕으로 화면과 이동 흐름을 연결했다. **기획 확정 문서를 수정하거나 미정 규칙을 확정한 작업이 아니다.** 기존 CSS·색상·시각 스타일을 그대로 사용한다.

기준 문서 경로는 `docs/design/` 기준이며 확장자는 `.md`다. 하단 메뉴는 활동 / 내 정보 / 보관함 / 상점 / 채무다. 숙박을 유료 수면처럼 노출하던 이전 화면은 제거했다.

## 목업의 경계

- 시작은 현금 0원·물품 없음이다. 별도로 `내 정보 → 화면 검토 도구`에서 테스트용 현금·물품을 불러와 유료 구매를 확인할 수 있다. 회차·부활 기능이 아니다.
- `src/content/preview.ts`의 보상·가격·보관 4칸·동시 등록 2개·테스트 현금 50,000원은 **모두 화면 검증용 예시**다. 실제 수치가 아니다.
- 목업 현금·물품·등록 상태는 메모리에서만 변경한다. 새로고침하면 초기화한다. 관심 매물만 기존 IndexedDB 저장을 사용한다.
- 시간·포만감·체력·피로도·이자·능력치·확률은 계산하지 않는다. 헤더 시각/상태도 표시 예시다. 알바·급식·수면은 확인/결과 화면만 연결하고 보상이나 회복을 적용하지 않는다.
- 나눔/수집/구매는 고정 예시 물품을 메모리 보관함에 넣고, 구매/판매 시 목업 현금을 바꾼다. 실제 생성·매칭·감정·경제 엔진은 없다.
- 구매 전 확인의 소모 자원은 경우마다 다르고 미정이므로 실행을 보류한다. 구매 후 별도 가치 확인은 고정된 결과 화면을 보여주는 예시다.
- 구매 네고는 예시 가격 선택과 예시 수락 응답만 연결한다. 판매자 판단 규칙을 구현한 것이 아니다.
- 구매 문의는 개발용 버튼으로만 발생한다. 거절 뒤 재제안, 반복 거절 뒤 파토를 고정 예시로 보여준다. 확률·가격 인상 폭·시간 규칙이 아니다.
- 문의가 대기 중이면 모든 하단 메뉴와 홈 이동을 막아 필수 응답을 우회하지 못하게 한다. 파토 시 등록 글과 다른 문의를 모두 닫는다. 수락 후 다른 문의의 처리는 미정이며 목업에서는 화면 상태를 정리한다.
- 등록 물품도 보관 공간을 차지한다. 매각처 판매 전에는 등록 취소가 필요하다. 등록 중 폐기 규칙은 미정이며 목업에서는 먼저 취소하도록 제한한다. 버리기의 복구·금전 비용은 확정하지 않는다.
- 매각처 가격은 방문 화면을 연 뒤에만 표시한다. 취급 품목·금액은 예시며 네고 입력은 제공하지 않는다.
- 채무 상환 입력은 확인 안내까지만 연결한다. 이자·원금·현금을 변경하지 않는다. 상점 구매 품목, 치료 종류, 사망 판정, 실제 날짜 진행, 등록 만료는 미구현이다.

## 실행과 검증

```sh
npm ci
npm run typecheck
npm run lint
npm run format:check
npm run build
npm run preview -- --port 4180
```

별도 터미널에서 `python3 scripts/verify-screens.py`로 Chromium 화면 흐름을 검증한다. Python Playwright와 Chromium이 필요하다. `SCREEN_BASE_URL`, `CHROMIUM_PATH`로 주소와 실행 파일을 바꿀 수 있다. 스크린샷은 커밋 제외 `work/`에 저장한다.

다음 단계는 화면을 보며 빠진 선택지와 화면 순서를 검토한 뒤, 실제 시간·상태·자원 소모 수치를 사용자와 결정하는 것이다. 이 파일은 구현 범위 안내이며 게임 규칙의 원본은 계속 `docs/design/`이다.
