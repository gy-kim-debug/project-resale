# 시스템과 미확정 규칙

> 이전 기획의 참고 자료입니다. 현재 설계는 사용자가 처음부터 결정해 작성하는 [게임 설계서](GAME_DESIGN.md)를 따릅니다. 아래 내용은 새 설계에 자동 반영하지 않습니다.

이 문서는 시스템 개요입니다. 세부 규칙의 확정 상태·비교안·결정 순서는 [게임 상세 설계 기준서](GAME_DESIGN.md)를 기준으로 합니다. 목업 화면이나 기존 코드 값은 확정 규칙의 근거가 아닙니다.

## 확정 요구사항

- 거래: 카테고리, 판매자 가격과 실제 가치의 차이, 상태·숨은 결함, 협상, 매입, 감정, 수리, 보관, 재판매, 희귀품, 시장 변동을 단계적으로 구현한다.
- 생존: 현금, 채무, 발생 이자, 배고픔, 피로, 건강, 시간을 관리한다. 시간 경과와 생활 행동이 생존 상태에 영향을 준다. 악화 시 건강 감소나 행동 제한을 고려한다. 생존 수치가 실제 가치·거래 확률을 직접 보정하지 않는다.
- 채무: 초기 원금 10,000,000,000원. 원금과 이자를 구분하고 일부 상환을 허용하며, 전액 상환 시 클리어한다.
- 이벤트: 특별 거래, 사고·손실, 시장 변화, 인물 관계, 생존 사건. 시간·자산·보유품·거래 이력·이전 선택에 따른 조건과 후속 사건 연결을 지원할 수 있어야 한다.
- 시간: 행동할 때만 진행한다. 글을 읽거나 앱을 꺼두면 정지한다. 시간 비용이 있는 행동과 소요 시간은 미정이다.
- 종료: 사망하면 게임이 종료된다. 회차·직업 상태·계승·영구 성장 시스템은 두지 않는다. 사망 판정과 종료 처리는 생존 엔진 단계에서 구현한다.
- 탐색: 활동 / 내 정보 / 보관함 / 상점 / 채무의 5개 탭. 장터·음식 먹기·잠자기·숙박은 활동 내부 화면이다.

## 아직 정하지 않은 규칙

| 영역     | 미확정 사항                                                                                                 |
| -------- | ----------------------------------------------------------------------------------------------------------- |
| 거래     | 가격 분포, 실제 가치 모델, 협상식, 정보 공개 비용, 감정 정확도, 수리 비용·성공률, 판매 대기 시간, 보관 한도 |
| 생존     | 수치 범위·초기값, 시간 단위, 행동 비용, 감소율, 건강 악화와 행동 제한 기준                                  |
| 채무     | 이자율, 단리·복리, 정산 주기, 반올림, 원금·이자 상환 우선순위, 독촉 규칙                                    |
| 이벤트   | 발생률, 조건 우선순위, 중복·재발 규칙, 연속 사건 중단 조건                                                  |
| 종료     | 사망 판정, 종료 시 저장 정책, 파산 처리 규칙                                                                |
| 상점     | 판매 품목, 이용 방식, 가격                                                                                  |
| 오프라인 | 앱 설치·캐시 업데이트 정책, 행동 도중 종료 시 저장·재개 방식                                                |

## 목업 전용 값

DAY 1 09:00, 배고픔 20, 피로 15, 건강 100, 0~100 미터, 매물 가격·상태는 UI 확인용이다. 확정된 경제·생존 규칙이 아니다. 관심 매물만 저장하며 원금과 현금은 시작 조건을 표시한다.

## 제안 (승인된 게임 규칙 아님)

먼저 고정 시드 기반 난수와 간단한 매입·재판매 한 사이클을 설계한다. 이벤트는 데이터의 조건·효과·후속 ID와 실행 로직을 분리하고, 확률과 가격은 콘텐츠 데이터에서 조정할 수 있게 한다.
