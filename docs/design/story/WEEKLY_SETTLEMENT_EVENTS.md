# 매주 상환 완료 이벤트

## 사용자 요청과 적용 범위

사용자는 매주 빚을 갚을 때마다 이벤트가 나오도록 요청했다. 개발자 구현 정책으로 ‘주간 의무 원금과 정산 이자를 모두 납부해 다음 주로 넘어간 시점’에 짧은 대화 이벤트를 한 번 표시한다. 주중 일부 원금 상환, 정산 진입, 의무 원금만 납부한 시점에는 띄우지 않는다.

기존 원금·이자·상환 비용·주간 행동·사업 수입 규칙을 변경하지 않는다. 이벤트는 보상이나 추가 비용을 발생시키지 않는다. 최종 채무 완납은 주간 이벤트 대신 성공 엔딩, 미납 종료는 기존 실패 엔딩을 우선한다.

## 발생 순서와 저장

1. 기존 정산 경로에서 의무 원금과 이자를 차감하고 다음 주 상태를 확정한다.
2. 직전 상태에서 해당 주 누적 원금 상환액을, 납부 전후 누적 상환액 차이에서 정산 이자를 기록한다. 자발적으로 미리 갚은 원금도 그 주 상환액에 포함한다.
3. 납부 주차·실제 납부액·남은 원금·현금·사업 수입·현재 원금 기준 다음 주 의무 원금/이자·상황을 `StoryScene.settlement`에 고정한다.
4. `StoryState.lastSettlementWeek`를 납부 주차로 기록하고 `weekly` 장면을 시작한다. 이 처리는 기존 저장 경로로 연출 전에 저장한다.
5. 대사·답변·마지막 확인만 진행한다. 대화를 끝내도 원금·이자·현금·행동·난수는 다시 변경하지 않는다.

매주 이벤트는 무작위 확률과 일반 거래 이벤트 쿨다운에 막히지 않는다. 같은 주의 완료 이벤트를 다시 생성하지 않는다. 중간에 종료하면 같은 장면·대사·답변 분기에서 이어진다. 이전 저장에는 완료한 주차의 이벤트를 소급 발송하지 않고, 다음 정상 납부부터 적용한다.

## 상황별 내용 — 개발자 작성

우선순위대로 상황 하나를 고른다. 경제 난수를 추가 추첨하지 않는다.

| 상황             | 조건                                          | 내용                                       |
| ---------------- | --------------------------------------------- | ------------------------------------------ |
| 첫 번째 납부     | 1주차 납부                                    | 처음 한 주를 버텼다는 안도와 채권자의 확인 |
| 끝이 보이는 숫자 | 남은 원금이 초기 채무의 10% 이하              | 끝이 가까워졌다는 주인공의 감정            |
| 절반을 지나      | 남은 원금이 초기 채무의 50% 이하              | 절반 이상 갚았다는 변화                    |
| 남겨둔 잔액      | 현금이 현재 원금 기준 다음 주 정산액보다 적음 | 이번 주를 넘겼지만 다음 주가 걱정되는 장면 |
| 일하는 동안에도  | 이번 정산에서 받은 사업 수입이 있음           | 거래 외의 수입이 상환을 돕는 장면          |
| 빗소리 속의 송금 | 나머지 주차 순환                              | 반지하의 비와 송금 완료 화면               |
| 접어둔 명세서    | 나머지 주차 순환                              | 접어놓은 명세서와 언젠가 끝날 빚           |
| 잠깐의 고요      | 나머지 주차 순환                              | 납부 뒤 잠깐 찾아온 고요                   |

마지막 세 장면은 주차에 따라 순환한다. 상황이 반복돼도 해당 주 실제 납부액·남은 원금·다음 주 명세는 해당 납부 시점의 값이다. 부모 행방·새 채무·추가 상환 조건 같은 새로운 주인공 설정은 만들지 않는다.

## 대화 선택

기본 대화는 주변 묘사 → 채권자의 실제 납부 확인 → 주인공의 상황별 반응 → 채권자의 확인과 남은 원금 순서다.

- ‘다음 주 납부액을 묻는다’ → 주인공이 직접 질문하는 대사, 채권자가 현재 원금 기준 다음 주 의무 원금·이자를 답하는 대사, 주인공의 응답으로 이어진다. 앞으로 원금을 더 갚으면 이자가 달라진다고 명시한다.
- ‘통화를 마친다’ → 주인공이 확인했다는 대사, 채권자의 인사, 전화를 내려놓는 묘사로 이어진다.
- 버튼 문구를 대사로 복사하지 않는다. 두 분기 모두 추가 비용·행동 소모·경제 결과 차이는 없다.
- 마지막 ‘다음 주 시작’으로 대화를 닫는다. 실제 주차 전환과 납부는 이미 저장됐으므로 중복 실행하지 않는다.

## 연출과 조작

사용자 캐릭터가 있는 방 → 실제 납부 내역을 띄운 휴대전화 클로즈업 → 창가/얼굴 구도를 사용한다. 방의 색감은 상황에 따라 달라지고 비 장면에는 빗방울이 움직인다. 무대 위치·높이는 모든 대사와 선택지에서 고정한다.

기존과 같이 제목은 중앙, 스킵은 오른쪽, 다음은 텍스트로 표시한다. 스킵은 각 대화 묶음의 마지막 선택 지점까지 이동한다. 새 효과음은 추가하지 않으며 동작 줄이기에서는 정지 화면을 사용한다. 이벤트 알림 우편은 새로 만들지 않는다.

## 미리보기와 책임

- `previewSettlement()`는 실제 슬롯을 건드리지 않는 새 게임 복사본의 납부 이벤트를 보여준다.
- `previewSettlement('rain', 4)`처럼 상황과 예시 주차를 지정할 수 있다. 상황은 first/tight/business/halfway/near/rain/envelope/quiet, 주차는 1~12다. 강제 상황 선택은 미리보기만의 기능이다.
- `content/settlementEvents.ts`: 상황·대사·영수증 데이터 유형.
- `domain/settlementEvents.ts`: 실제 납부 전후 상태로 영수증과 상황 결정.
- `domain/story.ts`, `domain/engine.ts`: 발생·중복 방지·대화 분기·완료 처리.
- `storage/validation.ts`: 납부 주차와 영수증·금액·대사 위치 검증.
- `components/SettlementStage.tsx`: 장면 구도와 도트 연출.

기존 1회성 ‘채권자의 방문’ 이벤트를 저장 중이었다면 그대로 이어간다. 기존 거래 이벤트 18종과 그 미리보기 목록은 유지하며, 주간 상환 이벤트를 별도 장면으로 추가한다.
