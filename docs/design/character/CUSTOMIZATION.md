# 새 게임 캐릭터 설정

## 사용자 요청

새로 시작할 때 캐릭터 모습과 닉네임을 설정할 수 있다. 선택한 캐릭터를 내 정보에 표시하고 행동·도트 대화 연출에도 같은 모습으로 사용한다.

후속 사용자 요청(2026-11-04): **여자·남자 아바타 2종**, 각각 **헤어·옷 종류·옷 색상·피부색**을 고를 수 있게 한다. 성별에 따른 헤어/의상 제한이나 능력치 차이는 요청하지 않았다.

## 현재 설정 — 첫 적용 구성

- 아바타: 여자 / 남자. 얼굴과 몸 실루엣의 픽셀을 구분한다.
- 헤어 5종: 짧은 머리, 긴 머리, 모자, 단발, 묶은 머리.
- 옷 종류 5종: 재킷, 티셔츠, 후드, 코트, 원피스. 소매·앞면·후드·기장·하단 형태를 실제 도트로 다르게 렌더링한다.
- 옷 색상 6종: 민트, 블루, 앰버, 로즈, 차콜, 크림.
- 피부색 3종: 밝은 톤, 중간 톤, 짙은 톤. 얼굴·목·손·노출된 팔/다리에 같은 팔레트를 적용한다.
- 총 2×5×5×6×3 = 900개 조합. 모든 헤어·옷·색상을 두 타입에서 자유롭게 선택한다. 타입을 바꿔도 다른 선택을 자동 초기화하지 않는다.
- 선택 즉시 공유 도트 컴포넌트로 미리보기. 색상은 견본도 표시하고, 긴 모바일 설정 화면에서는 미리보기를 위에 유지한다.
- 닉네임: 1~12자. 문자·숫자·공백·`_ . -` 허용. 앞뒤 공백 제거/NFKC 정규화. 기존처럼 닉네임만 키보드 직접 입력이다.

선택은 외형과 표시 이름에만 적용한다. 성별·옷·헤어·피부색·닉네임은 경제 RNG, 거래 성향, 능력치, 물건 가치, 확률, 자금에 영향을 주지 않는다. 옷은 장비나 능력치 아이템이 아니다. 성별을 직업/나이/회차 설정으로 확장하지 않는다.

## 저장과 이전 게임

`Game.player`의 선택 필드에 nickname과 appearance를 저장한다.

- 기존 `hair` / `outfit` / `skin` 키를 유지한다. `outfit`은 기존 저장에서 옷 **색상**을 뜻하며 의미를 바꾸지 않는다.
- 새 `avatar?: 'female' | 'male'`, `clothing?: 'jacket' | 'tshirt' | 'hoodie' | 'coat' | 'dress'`는 선택 필드로 추가한다.
- 기존 프로필에 두 필드가 없다면 원래 기본 체형·재킷 도트로 그리며 원본 프로필에 새 필드를 강제로 기록하지 않는다. 기존 긴 머리/모자와 색상·피부색도 그대로 유지한다.
- 프로필 자체가 없는 게임은 기존처럼 기본 캐릭터와 플레이어 이름으로 표시한다. 이름을 임의로 새로 저장하지 않는다.
- 새 게임 기본은 남자·짧은 머리·재킷·민트·중간 톤이며 생성 화면에서 자유롭게 고른다.
- 백업/슬롯 읽기는 기존 필드 누락을 허용하되 잘못된 새 타입·옷 키는 거절한다. 저장 형식과 IndexedDB 버전은 유지한다.
- 슬롯마다 독립적이며, 프로필을 바꾸지 않고 게임만 이어서 불러올 수 있다. 기존 게임의 외형 편집/꾸미기 상점은 이번 범위에 추가하지 않는다.

## 코드 책임

- `content/player.ts`: 타입·헤어·의상·팔레트 목록과 기본값.
- `domain/player.ts`: 프로필/닉네임 검증과 이전 게임 표시 정책.
- `PixelCharacter`: 24×32 정수 좌표 도트. 두 체형·헤어·소매·앞면·기장 및 팔레트를 조합한다. 기존 애니메이션용 몸/팔다리 그룹은 유지한다.
- `StartMenu`: 아바타→헤어→옷 종류→옷 색상→피부색 선택과 미리보기.

생성 미리보기·슬롯 카드·이어하기 화면·내 정보·행동 로딩·시작/엔딩/이벤트 장면·콘솔 미리보기에서 공유 컴포넌트와 선택 프로필을 재사용한다. 상대 NPC의 고정 도트는 플레이어 외형 선택의 영향을 받지 않는다.
