# 판매 유동성·난이도 조정 1차

## 사용자 피드백과 우선순위

직접 플레이에서는 자금이 빠르게 증가하고 중후반 상환액이 작게 느껴졌다. 아르바이트·즉시 판매 사용이 적은 원인으로 빠른 게시판 판매가 지목됐다. 이 경험을 이전 자동 전략 결과보다 우선한다. **원금 증가를 1.5배로 낮추는 제안은 보류하고 현행 2배를 유지한다.** 사업 90% 매각도 이번에는 추가하지 않는다.

이번 적용은 상환액을 더 늘리기 전에 판매 회전 속도를 조정하는 단계다. 시작금 50만원·20행동·금액 단위·사업·생존 수치 없는 구조를 유지한다. 매물의 실제 가치/가품 확률이나 수리 성공률을 낮추지 않는다.

## 기존 문제

- 등록 완료 다음 행동부터 문의를 조회하고 매 행동 재조회했다.
- 시세 110% 이하 가격은 조회마다 85% 확률이고 문의가 한 번에 2개 왔다.
- 정상가에서 수익을 크게 양보하지 않고도 빠르게 현금이 돌아와 다음 물품에 재투자하기 쉬웠다. 문의가 없는 구간이 짧아 고정 임금과 60% 즉시 판매의 상대적 이점이 작았다.

## 적용한 초기 조정값

| 항목                     | 이전               | 조정               |
| ------------------------ | ------------------ | ------------------ |
| 첫 문의 확인             | 등록 완료 후 1행동 | 등록 완료 후 2행동 |
| 재확인 간격              | 1행동              | 2행동              |
| 글 유효 기간             | 완료 후 6행동      | 완료 후 8행동      |
| 시세 85% 이하            | 85%                | 85%                |
| 시세 85% 초과–110% 이하  | 85%                | 60%                |
| 시세 110% 초과–135% 이하 | 50%                | 35%                |
| 시세 135% 초과–160% 이하 | 50%                | 15%                |
| 시세 160% 초과           | 20%                | 5%                 |

확률은 문의 조회 1회 기준이며 해당 시점 시세에 따라 판정한다. 글 전체의 최종 판매 확률이나 판매 보장은 아니다. 메뉴에 이 규칙을 설명하는 공략 문구를 추가하지 않는다. 구매자 제안 범위/네고 규칙/문의 2개/실제 거래 1행동은 유지한다.

일반적으로 2·4·6번째 행동에서 문의 기회가 있고 8번째에 만료될 수 있다. 다른 문의 응답 중이면 확인이 늦어질 수 있다. 기존 저장의 예약 시점/만료 시점을 재설정하지 않으며 이후 재확인 간격부터 적용한다. 실시간/오프라인으로 확률을 반복 추첨하지 않는다.

## 비교 결과

같은 시드 1–30으로 변경 전 2전략 60회, 초기 6행동 글 2전략 60회, 조정 후 8행동 글 4전략 120회, 별도 80% 등록 초기 2전략 60회를 실행했다. 모두 실제 엔진을 사용한다. 확률·타이밍 변경으로 이후 난수 소비와 의사결정 경로도 달라진다. **사람의 클리어율이나 개별 파라미터의 독립 효과를 뜻하지 않는다.**

| 전략                           | 이전 클리어 | 조정 후 클리어 | 판매에 연결된 문의의 대기 중앙값 |
| ------------------------------ | ----------: | -------------: | -------------------------------: |
| 성장형 병렬 판매               |       15/30 |           7/30 |                        1 → 3행동 |
| 병렬 판매 + 대기 중 아르바이트 |       19/30 |           6/30 |                        1 → 3행동 |

대기 지표는 실제 판매된 물품의 마지막 등록 완료부터 해당 거래로 이어진 문의 묶음이 도착할 때까지다. 같은 글에서 문의가 여러 차례 오면 최종 매칭 시각을 사용한다. 모든 판매 글의 평균 대기/첫 문의 시간으로 해석하지 않는다. 글 만료/미판매 재고도 별도로 집계한다.

6행동 유효 기간을 그대로 둔 초기안의 병렬 전략에서는 30회 전체에 만료 521건이 발생했다. 8행동으로 늘린 조정안은 164건이었다. 두 집계는 회차 길이도 달라 개별 글 만료율은 아니지만, 과도한 재등록 반복을 줄이기 위해 기한을 연장했다.

80%에만 고정 등록한 정책은 조정 후 아르바이트 미병행/병행 각각 1/30 클리어였다. 할인은 수익률을 낮추므로 항상 유리한 전략이 아니다. 정상가로 기다리기/급한 시점 할인/즉시 판매를 상황에 맞게 선택하도록 둔다. 대기 중 아르바이트의 현금 수입은 실제로 지급되지만 그 돈으로 더 큰 위험 거래를 자동 선택하는 봇에서는 단순 대기보다 높은 클리어를 보장하지 않는다.

결과 요약은 [LIQUIDITY_RESULTS.json](LIQUIDITY_RESULTS.json), 원자료는 `work/liquidity-before`, `work/liquidity-after`, `work/liquidity-discount`, `work/liquidity-final`에 보관한다. 변경 후 결과에는 src 파일의 SHA-256 스냅샷을 남겼다. 분석 도구의 지표명 matchedInquiryWait는 초기 실행 원자료에서 firstInquiryWait라는 이름으로 기록됐으며 계산 방식은 같다.

재현 예: `AUDIT_SEEDS=30 AUDIT_STRATEGIES=parallel,parallel-jobs,parallel-80,parallel-80-jobs AUDIT_OUTPUT=work/liquidity-final npm run audit:economy`. 기본 5전략 실행도 계속 지원한다.

## 플레이에서 확인할 것

- 정상가 매물에 돈이 묶이는 시간이 실제로 생겼는가.
- 할인/정상가/높은 가격의 체감 차이가 있는가.
- 급히 현금이 필요할 때 60% 즉시 판매가 의미 있는가.
- 아르바이트가 대기 시간을 활용하는 선택이 되는가.
- 만료/재등록이 단순 반복 작업으로 느껴지지 않는가.
- 중후반에도 납부 압박이 약하면 다음 비교에서 원금 증가 배수/단계별 납부액을 검토한다. 현재 자동 전략만으로 최종 난이도를 확정하지 않는다.
