# 100원 단위 금액과 반올림

## 사용자 확정

모든 금액의 최소 단위를 100원으로 통일하고 그 아래 자릿수는 반올림한다. 1,049원은 1,000원, 1,050원은 1,100원이다. 무료 거래·빈 잔액·완납의 0원은 유지한다.

## 계산과 입력

- `domain/money.ts`의 `roundMoney`와 `moneyRatio`를 공통 사용한다. 비율 계산은 BigInt 중간 연산으로 한 번만 100원 단위 반올림하여 큰 금액의 정밀도와 50원 경계를 지킨다.
- 현금·채무·이자·이번 주 상환액·금전 실적·물건의 기본/실제 가치·매입가·시장 시세·매물/판매가·흥정 금액·검증/수리비·즉시 판매 금액에 적용한다. 횟수·시각·확률·이율은 반올림 대상이 아니다.
- 직접 입력한 금액도 실제 적용할 금액을 미리 표시하고 제출/엔진에서 같은 방식으로 반올림한다. 100원보다 작은 입력이 0원으로 반올림되면 유료 등록·상환은 거절한다. 50원 입력은 100원이 된다. 소수·음수·비정상 입력과 지원 상한 초과 금액은 기존처럼 거절한다.
- 검증비는 최소 100원, 수리비는 기존 최소 300원이다. 계산 결과 0원인 실제 가치·시세·이자는 0원이다. 즉시 판매가 0원이면 판매하지 않는다.
- 흥정 선택지는 반올림 후 중복과 이전 제안 이하/현재 역제안 이상 금액을 제거한다. 사이에 유효한 100원 단위 금액이 없으면 최종가로 마무리한다. 구매자 재제안도 최소 100원 이상 올라가며 지불 한도를 넘지 않는다.
- 생성 매물의 기본 1,000원 가격 간격과 경매의 100만 원 입찰 간격은 더 큰 100원 배수로서 유지한다. 급처의 90% 계산은 100원 단위로 반올림한다.
- 주간 의무 원금의 50,000원·100,000원·200,000원… 규칙은 유지한다. 이자는 원금 납부 후 계산하고 기존 원 단위 올림 대신 100원 단위 반올림한다.

## 기존 저장과 거래

저장 버전 2에 `moneyUnit: 100`을 기록한다. 구 저장의 금융·물품·협상·판매·문의·견적·금전 실적을 반올림해 복원한다. 물품 ID·태그/숨은 사실·자산 소유·주차/행동·난수·읽음 메타데이터는 재설정하지 않는다. 과거 대화와 기록의 원화 금액 표기도 맞춘다. 현재 진행 중인 유료 제안의 대사는 최소 가격 보정과 함께 맞추어 표시 금액과 수락 금액이 다르지 않게 한다.

구 유료 매물/판매 가격이 100원 미만이면 최소 100원으로 보정하여 무료나눔으로 바뀌지 않게 한다. 매입가는 실제 지불 기록을 반올림하므로 0원이 될 수 있다. 원금·이자가 모두 0원으로 반올림되면 완납 처리한다. 경매는 기존 입찰 간격에 대한 위치를 유지하면서 새 시작가에 정렬하므로 경쟁자의 한도를 다시 추첨하지 않는다.

새 정책 저장은 100원 배수 정합성을 검사한다. 구 데이터와 백업은 변환 후에도 검증하며, 잘못된 데이터는 기존 진행에 덮어쓰지 않는다. 이미 반올림된 데이터를 다시 읽어도 금액은 변하지 않는다. 지급과 차감은 표시 금액 그대로 처리하고 거래 후 잔액을 따로 반올림해 차액을 만들지 않는다.
