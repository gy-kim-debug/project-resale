# 택배 전용 거래 이벤트 — 2026-11-19

## 사용자 요구

택배 거래에는 직거래와 다른 사건·선택지·연출을 사용한다. 같은 만남 이벤트에서 일부 단어만 바꾸는 방식으로 처리하지 않는다.

## 적용 구조

- 택배 구매와 판매는 별도의 이벤트 풀을 사용한다. 직거래의 현장 네고·만남 장소 변경·현장 점검은 택배에서 새로 뽑지 않는다.
- 전체 이벤트는 기존 18종과 택배 전용 4종으로 22종이다. 택배 4종에 각각 3개 상황을 작성했다.
- `content/parcelEvents.ts`: 택배 종류·대사·질문·선택 후 발화와 상대 반응.
- `domain/story.ts`: 거래 방식과 남은 행동에 맞는 풀 선택. 기존 발생 확률과 경제 난수 분리는 유지한다.
- `domain/eventDepth.ts`: 택배 전용 선택지와 원격 대화. 선택 후 실제 가격·행동을 `domain/engine.ts`에서 처리한다.
- `components/ParcelStage.tsx`: 혼자 포장하는 캐릭터, 휴대전화 속 상대, 포장 상자·카메라·운송장·택배차를 표시한다. 대사·선택지가 바뀌어도 무대와 인물 배치는 고정한다.
- 이벤트가 없는 일반 택배 거래의 완료 로딩도 `택배를 받는 중…` / `택배를 발송하는 중…`과 택배 장면을 사용한다. 직거래는 기존 교환 장면을 유지한다.

## 사건과 실제 선택 효과

아래 수치는 사용자에게 위임받아 정한 초기 구현 정책이며 조정 가능하다. 금액은 공통 100원 단위 반올림을 적용한다.

| 종류                        | 상황                                                     | 선택                                                           | 실제 효과                                                                                                             |
| --------------------------- | -------------------------------------------------------- | -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 재포장 요청 `parcelPacking` | 상자/완충재가 맞지 않아 재포장이 필요                    | 재포장·접수를 기다리기 / 취소                                  | 기다리면 원래 합의 금액의 95%로 구매, 총 2행동. 취소는 무료이며 구매 대화 종료                                        |
| 수거 마감 `parcelDispatch`  | 가까운 지점의 수거·방문 접수가 끝남                      | 다음 접수까지 기다리기 / 오늘 가능한 다른 지점으로 접수 / 취소 | 기다리면 합의 금액의 95%로 구매·2행동. 오늘 다른 지점 접수는 원래 금액·1행동. 취소 무료                               |
| 발송 전 사진 `parcelPhotos` | 구매자가 외관과 구성 사진을 더 요구                      | 사진을 준비하고 확인받기 / 현재 사진 기준으로 금액 양보 / 취소 | 사진 준비 후 원래 구매 문의 금액에 판매·2행동. 현재 사진 기준은 문의 금액의 95%에 판매·1행동. 취소는 해당 문의만 종료 |
| 수령지 변경 `parcelAddress` | 발송 전에 수령 정보가 바뀌어 운송장 재작성·재접수가 필요 | 수정 정보를 확인해 다시 접수 / 취소                            | 원래 문의 금액으로 판매·2행동. 취소는 해당 문의만 종료. 잘못된 기존 정보로 그대로 발송하는 선택은 제공하지 않음       |

- 추가 설명·질문은 무료다. 2행동은 대화를 읽는 비용이 아니라 재포장·사진 준비·접수 등 거래를 마무리하는 전체 작업 비용이다.
- 남은 행동이 1회이면 구매는 1행동 선택이 있는 수거 마감, 판매는 금액 양보 선택이 있는 사진 요청에서만 추첨한다. 2행동 거래만 가능한 사건으로 불필요한 취소를 강요하지 않는다.
- 구매 확정 전에는 공통 금액 검사와 남은 행동 검사를 한다. 오류·오래된 선택·재실행은 현금/물품/난수를 원상 유지한다.
- 준비·대기 뒤 결제와 물품 이전은 기존 추상화대로 한 번에 완료한다. 새 실시간 배송 대기, 별도 배송 목록, 배송료, 물품 파손 확률은 추가하지 않는다.
- 사진과 포장 작업은 물품의 실제 가치·등급·진품 여부를 다시 계산하거나 감정 완료 상태로 바꾸지 않는다. 미개봉 물품을 사진 때문에 개봉하지 않는다.
- 택배 대기만으로 단골/소개 보상을 새로 만들지 않는다. 원래 직거래 대기 사건의 기존 후속 소개 처리는 유지한다.

## 저장·구버전 진행 중 장면

- 새 이벤트 ID와 `tradeMethod: parcel`을 기존 선택적 장면 데이터에 저장한다. 저장 형식 버전은 올리지 않는다.
- 저장 검증은 실제 택배 가능한 물품과 택배 방식으로 연결된 거래인지 검사한다. 직거래 장면을 택배 전용 ID로 위조한 데이터는 거절한다.
- 구 저장에서 이미 추첨되어 진행 중인 이벤트는 ID·가격·행동 수·효과를 유지한다. `content/legacyParcelEvents.ts`가 화면 제목·접수 일정·사진 문의·포장 대화만 택배로 맞춰 표시한다. 거래를 새로 추첨하거나 과거 선택을 되돌리지 않는다.
- 대사 진행·선택·결과 장면·새로고침에서 거래를 중복 실행하지 않는다. 인물의 외형과 기존 슬롯 데이터도 유지한다.

## 검증

기존 이벤트 전체 분기에 택배 12개 상황을 포함하고, `tests/parcelEvents.test.ts`에서 거래 방식별 풀 분리, 마지막 행동의 선택 가능성, 분기별 결제·행동·물품 가치 보존, 재실행 방지, 구 장면 호환, 택배 완료 연출을 검증한다.
