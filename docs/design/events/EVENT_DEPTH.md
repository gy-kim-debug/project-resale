# 이벤트 심화 — 18종·54개 상황

## 사용자 요청과 유지하는 결정

사용자가 ‘이벤트를 더 깊게, 일어나는 일도 다양하게’ 해 달라고 요청했다. 기존 8종을 18종으로 확장하고, 각 사건에 서로 다른 상황 3개씩 작성했다. 아래의 구체적 수치와 분기 구성은 요청 범위에서 개발자가 정한 첫 적용 정책이다.

- 긴 메인 스토리는 시작과 엔딩에만 둔다. 이번 확장은 거래 중의 짧은 사건과 후속 연락이다.
- 직접 입력 없이 대사 터치·다음·선택지를 사용한다. 제목 중앙/스킵 오른쪽, 도트 영역 고정, 아래 대화만 스크롤하는 UI를 유지한다.
- 읽기와 질문에는 돈·행동·경제 난수가 들지 않는다. 스킵은 현재 대화의 선택 지점까지만 진행한다.
- 매물의 실제 가치·진위·상태를 대화로 미리 감정하지 않는다. 구매 전에는 판매자가 밝힌 정보와 주장만 알 수 있다.
- 이미 생성된 가치·희귀 확률·최대 3배 상한을 새 사건에서 재추첨하거나 올리지 않는다. 배고픔/체력/피로 시스템도 추가하지 않는다.

## 대화의 깊이

각 종류에 실제로 다른 사정 3개를 작성했다. 예를 들어 구성품 누락도 ‘상자 안 부속품 실종 / 이사 짐에 섞인 케이스 / 가족이 따로 쓰는 구성품’으로 나뉜다. 사연은 단순히 같은 문장 끝만 바꾼 것이 아니라 장소·거래 목적·상대 요청이 다르게 구성된다.

대화는 **상황 → 선택적 질문 → 거래 결정 → 상대의 반응**으로 진행한다. 해당 사건에 맞춰 사정·근거·거래 조건·이전 이야기를 물을 수 있다. 질문은 각각 한 번만 가능하고 물었던 질문은 다시 표시하지 않는다. 여러 질문을 생략하고 바로 결정할 수도 있다. 구매·판매·취소 후 반응 2개 대사를 보여주며, 이미 반영된 자산은 반응을 다시 읽어도 중복 처리하지 않는다. 채권자 확인처럼 거래가 없는 짧은 안내는 별도 반응을 강제로 덧붙이지 않는다.

상대의 거래 성향도 반영한다. 큰 폭 흥정 구매자는 현장 재흥정, 신중한 구매자는 추가 확인이 후보에 더 자주 들어간다. 쿨거래 판매자나 급처·이사 태그는 출발 직전 거래의 조건이다. 가격 고정·쿨거래·신중한 성향은 말투에도 반영한다. 나이·성별로 거래 손익 확률을 보정하지 않는다.

실제 거래는 1행동이다. ‘기다린 뒤 거래’는 **추가 대기 1 + 거래 1 = 번개 2**를 명시하고 한 번에 처리한다. 남은 행동이 부족하면 해당 선택은 비활성화되며, 엔진도 자산 변경 없이 거절한다. 일반 화면 이동과 대화 읽기는 행동으로 계산하지 않는다. 원금 상환·정산·사업 규칙은 바꾸지 않는다.

## 후속 연락

- 예약 → 예약자의 재연락.
- 사연을 듣고 구매 → 같은 물건을 찾는 이전 주인.
- 단골 부탁 수락 또는 기다려 준 거래 → 소개받은 구매자.

후속 후보는 해당 선택 때 저장되며 **3행동 틱 뒤부터, 10행동 틱 이내**에 조건이 맞으면 발생한다. 물건을 이미 팔았거나 버렸다면 같은 물건을 다시 팔도록 요구하지 않는다. 소개 거래는 해당 종류 중 거래 가능한 물건을 찾는다. 다른 구매 문의·정산·진행 중 대화가 있으면 끼어들지 않으며, 후보가 만료될 수 있다. 후보는 최대 8개이며 같은 원인·대상의 중복 등록을 막는다.

예약을 받아 주면 그 판매 글의 다음 문의 확인을 5행동 틱 뒤로 미루고 판매 유효 기간을 최소 6행동 틱 확보한다. 예약자가 돌아와도 판매 수락은 다시 고른다. 예약금·위약금·강제 환불은 없다. 정산으로 주를 바로 넘기면 연락 기회를 놓칠 수 있다.

## 발생 빈도와 균형 — 첫 적용값

- 거래 직전 기본 확률 24%, 사건 완료 후 3행동 틱 간격은 유지한다. 사건 수가 늘었다고 매 거래마다 반드시 발생시키지 않는다.
- 새 구매 사건도 기존과 같은 후보 풀 안에서 선택한다. 못 본 종류를 우선하고 상황 번호는 안정된 별도 해시로 고정한다.
- 구매자 사건은 재흥정/추가 확인/예약 후보를 성향에 따라 고른다. 무료나눔과 고가 경매 결제에는 이 일반 구매 사건을 넣지 않는다.
- 행동 후에는 가능한 후속 연락을 먼저 확인한다. 이후 매물 정보 6%, 감정된 수집품 제안 12%, 기존 단골 연락 18% 및 경쟁자 제안 12%/요청 종류 35%를 순차 확인한다. 한 행동에 하나만 표시한다.
- 소개·수집가·이전 주인의 금액은 보유품에 대한 매입 제안이지 물건 가치 상승이 아니다. 시세가 바뀌어도 열린 제안 금액은 대화 도중 재추첨하지 않는다.
- 사건용 해시는 경제 난수를 소비하지 않는다. 실제 새 매물 탐색을 선택했을 때만 일반 시장 생성 난수를 사용한다.

## 저장과 이전

`Game.story.active`의 선택 필드로 `variant`, 질문 이력 `asked`, 현재 질문 응답 `branch`, 결정 후 `outcome`과 `decision`을 저장한다. `pending`에는 후속 후보 종류·대상·기한·필요 시 잠근 가격을 저장한다. 사건 자료는 콘텐츠 파일, 상태 변화는 도메인 엔진에서 처리한다.

- 기존 저장에서 이미 열린 8종 대화는 기존 대사 위치와 규칙을 그대로 유지한다. 새로운 사건부터 심화 형식을 적용한다.
- 질문 중·반응 중·예약 대기 중에도 저장/복원할 수 있다. 거래는 반응 표시 전에 한 번만 반영한다.
- 잘못된 질문/중복 질문, 상황 번호, 결과 상태와 거래 대상의 불일치, 중복/잘못된 후속 후보와 100원 미만 단위 금액을 검증에서 거절한다.
- 2행동 거래가 날짜 경계를 넘어도 내부 틱을 버리지 않는다. 주간 20행동·정산 시점·저장 유효성이 함께 유지된다.
- 새 우편을 대사마다 발송하지 않는다. 기존 우편 분류를 유지한다.

## 이후 조정 후보

질문의 효과는 현재 정보·확인·사연 제공이며, 모든 질문이 할인이나 보상을 주지는 않는다. 호감도 게이지·평판 점수·영구 해금은 추가하지 않았다. 실제 예약 취소, 환불 분쟁, 배송, 선입금 손실 등은 이번에 임의로 자동 손실 규칙을 확정하지 않았다. 현재 사건 빈도·매입 비율·대기 비용은 플레이를 보고 조정할 수 있다.

## 선택지 이름과 실제 대사 분리 (2026-11-04)

사용자 요청에 따라 ‘사정을 조금 더 묻기’ 같은 선택지 문구를 주인공의 말로 그대로 출력하지 않는다. `content/eventSpeech.ts`가 사건·질문 종류별로 자연스러운 발화 문장을 제공한다. 예: 예약 조건 질문 → “예약해 두면 거래 조건은 어떻게 되나요?”

구매·거절·예약·신고·기다리기 등 실제 결정을 하면 **주인공의 선택에 맞는 말 → 상대의 반응** 순으로 표시한다. 버튼 이름은 간결한 행동 설명을 유지한다. 선입금 요구의 답변도 3인칭 상황 요약을 상대의 대사로 출력하지 않고 상대가 직접 말하는 형식으로 구분한다. 금액·행동·저장·질문 중복 제한은 변경하지 않는다. 질문/반응의 저장 필드와 대사 개수를 유지하므로 재접속 시 거래가 반복되지 않는다.
