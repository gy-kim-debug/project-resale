# 이벤트 선택·결과 일치 검토 — 2026-11-17

## 사용자 요청

구매·판매 채팅은 먼저 문의한 사람이 먼저 말한다. 이벤트 전반의 선택지·선택 이후 대사·실제 결과가 어색하지 않도록 재검토한다.

## 적용 원칙

- 새 구매 문의는 플레이어의 상품 문의 → 판매자 답변 순서로 시작한다. 새 판매 문의는 구매자가 먼저 제안한다. 구매자의 인사를 자동으로 중복 선택하게 하지 않는다. 기존 저장된 대화는 당시 순서를 보존한다.
- 시작 답변에도 기존 입력 중 표시와 답장 간격을 적용한다. 다시 방을 열어도 인사·답변을 추가로 생성하지 않는다.
- 선택지 버튼은 행동을 요약하고, 선택 후 플레이어는 자연스러운 문장으로 답한다. 상대 반응은 선택 내용과 실제 처리 결과에 맞춘다.
- 질문은 돈·물건·행동·경제 난수·경험치를 바꾸지 않는다. 실제 거래/탐색/대기에만 기존 비용을 적용한다. 결과 대사를 넘기거나 다시 불러와도 거래를 재실행하지 않는다.
- 직거래/택배 맥락은 거래 종료 뒤 반응 장면까지 선택적 저장 필드로 유지한다. 택배에 현장 결제를 강요하지 않는다.
- 거래 취소는 해당 구매 대화만 종료한다. 같은 물건의 판매 문의는 해당 문의만 종료하며, 다른 구매자와 판매 글은 유지한다.

## 기타 화면과 저장

- 시작·엔딩 스토리는 선택으로 거래를 실행하지 않는다. 매주 정산 대화는 이미 실행된 납부의 확인이며 다시 차감하지 않는다.
- 복권은 정산 시 결정된 추첨 결과를 표시하고, 산책은 이미 실행된 산책 결과를 보여준다. 대사를 넘길 때 보상을 중복 지급하지 않는다. 조용한 산책에 고양이를 다시 만난다는 대사를 쓰던 부분을 수정했다.
- 선택지의 기존 번개 아이콘과 남은 행동에 따른 비활성화를 유지한다. 브라우저 경고창이나 직접 입력을 추가하지 않는다.
- 구 저장의 진행 중 장면은 새 필드 없이도 거래 대상을 통해 맥락을 복원한다. 새 필드에 불가능한 값을 가져오면 저장 검증에서 거절한다.

## 검증 범위

`tests/eventConsistency.test.ts`와 기존 이벤트·스토리·주간 정산·일상·채팅 테스트를 함께 실행한다. 문장의 자연스러움은 모든 상황의 대사와 질문을 검토하고, 자동 검증은 분기별 행동 소모·자산 변화·대상 보존·후속 반응·재실행 방지에 사용한다. 이후 콘텐츠 추가 시 이 표와 같은 기준으로 점검한다.
