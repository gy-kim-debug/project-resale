# 물품 특성별 수리 정책

## 사용자 요청

물품의 특성에 따라 수리가 가능한 것과 수리 자체가 성립하지 않는 것을 내부적으로 분류해 적용한다. 게임에는 수리 가능/불가 분류·태그를 노출하지 않는다.

## 이번 구현 정책 — 개발자 초기 분류

확률로 대상 여부를 새로 뽑지 않는다. 품목 이름의 예외 → 세부 카테고리 → 기존 품목명으로 카테고리 조회 → 오래된 미상 품목의 Kind 순서로 고정 판정한다. `src/content/repairPolicies.ts`는 콘텐츠 규칙, `src/domain/repairPolicy.ts`는 조회 로직이다. 새 저장 필드를 추가하지 않는다.

- 부품·기계·구조·원단·설비·표면을 다룰 수 있는 물품은 작업 대상이다. 실제 성공을 보장하는 뜻은 아니다.
- 책/레코드/구성 누락형 세트, 토지 자체, 원석·일부 컬렉션은 일반 수리로 기존 가치를 회복시키는 대상으로 취급하지 않는다. 진위·희소성·원본성·권리 관계를 수리로 바꾸지 않는다.
- 같은 카테고리도 개별 예외를 둔다. 도서·문구의 만년필/타자기, 취미·수집의 라디오/필름 카메라/피규어, 토지·창고의 창고/공장, 희귀 컬렉션의 역사적 악기는 작업 대상이다.
- 현재 240품목 중 221개 대상/19개 대상 외다. 아래 분류는 초기 콘텐츠 정책이며 추가 품목·플레이 피드백에 따라 조정할 수 있다.

## 화면과 실행

- UI는 `canAttemptRepair`로 기존 감정·B/C등급·미시도 조건만 확인한다. 품목 내부 분류로 버튼을 숨기거나 비활성화하지 않는다. A 이상·F·이미 시도한 물품의 기존 조건은 유지한다.
- 감정한 B/C 물품은 같은 작업 화면과 비용을 표시한다. 실제로 작업할 수 있는지를 미리 확정하는 성공률/예상 등급/예상 가치 표시는 제외한다. 성공한 뒤의 실제 등급·가치는 기존 결과 카드에서 확인한다.
- 실행은 `canRepair`로 품목 정책까지 검사한다. 대상 외면 일반 토스트 `작업을 진행하지 못했습니다.`로 종료한다. 대상 외 품목명/분류/이유를 별도 안내하지 않는다.
- 이 거부에는 현금·행동·시간·RNG·경험치·로그·수리 횟수·시도 기회를 소모하지 않는다. 숨은 비용이나 확정 실패 함정은 만들지 않는다.
- 대상 물품의 실제 작업은 기존 비용·시장별 능력·난이도·성공/실패·한 번 시도·최대 A등급 규칙을 그대로 사용한다. 실제 수리 실패는 기존대로 비용과 시도 기회를 소모한다.
- F등급의 기존 폐기 안내는 상태 등급 규칙이며, 이번 품목별 숨은 분류와 별개다.

## 기존 저장과 확장

기존 자산의 금액·등급·시세·시도 결과를 다시 뽑지 않는다. 카테고리가 없는 저장은 알려진 품목명을 조회하고, 알 수 없는 오래된 물품은 기존 Kind 기반 작업을 유지한다. 기존 물품에 이미 남은 `수리 가능합니다` 문구는 감정 결과 화면에서 새 상태 설명으로 표시하며 원본 저장을 강제로 덮어쓰지 않는다.

새 품목은 카테고리 기본 정책을 따르고 혼합 카테고리의 예외는 PRODUCT_REPAIR_OVERRIDES에 추가한다. 한도를 늘리거나 랜덤 이벤트/장비로 대상 여부를 바꾸는 기능은 이번에 추가하지 않는다.

## 검증

`tests/repairPolicies.test.ts`는 전체 카탈로그 커버리지·혼합 카테고리·기존 저장·UI 노출 분리·무손실 거부·실제 수리 계산을 검증한다. `scripts/prepare-repair-policy-fixtures.mjs`, `scripts/verify-repair-policies.py`는 실제 UI에서 분류가 노출되지 않고 대상 외 시도가 저장을 바꾸지 않는지 검증한다.
