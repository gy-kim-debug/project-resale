# 닉네임 외 선택지 전용 UI

## 사용자 확정

키보드로 직접 입력하는 부분은 새 캐릭터 닉네임 설정만 남긴다. 다른 입력은 후보를 보여주고 선택하는 방식으로 대체한다. 이 결정은 이전 판매 등록/구매자 흥정의 직접 가격 입력 및 장터 문자열 검색 정책을 대체한다.

## 적용 범위

- 판매 등록: 감정했다면 현재 가치와 60/80/120/150/200%, 매입가 후보를 제공한다. 미감정 유료 물건은 매입가와 같은 비율 후보를 사용한다. 실제 가치가 확인된 경우에만 현재 가치를 후보 계산에 사용한다.
- 미감정 무료나눔/수집품: 공개된 해당 시장 최저가의 50/100/200/500/1000% 희망 가격 후보를 제공한다. 숨은 실제 가치·진위·결함은 참조하지 않는다. 실제 가치가 0원으로 확인된 물건도 최소 가격 100원 또는 매입가 후보를 고를 수 있다.
- 구매자 흥정: 기존 등록가·절충가·소폭 인상 후보를 선택한 뒤 확정한다. 숨겨진 구매자 지불 한도를 후보 생성에 사용하지 않는다.
- 원금 상환: 상환 가능액(min(현금, 남은 원금))의 10/25/50/75/100%와, 감당할 수 있는 남은 의무 원금을 선택한다. 기존 가능한 만큼 상환 바로가기는 유지한다.
- 장터: 현재 매물의 품목을 목록에서 선택한다. 카테고리·관심·정렬과 함께 사용할 수 있다. 선택한 품목이 만료되거나 사라지면 선택 상태와 매물 없음 표시를 유지하며 해제할 수 있다. 검색어를 쓰는 입력란은 제거한다.
- 캐릭터 외형: 기존 라디오 선택을 유지하며 닉네임만 텍스트 입력이다.
- 백업: 기존 파일 선택기를 유지한다. 앱에서 JSON 문자열이나 경로를 직접 입력하는 칸은 만들지 않는다.

구체적인 가격 비율/후보 개수는 선택 UX를 위한 초기 구현값이며 경제·수요·흥정 확률을 변경하지 않는다. 후보는 100원 단위로 반올림하고 중복, 미확인 값, 범위 밖 금액을 제거한다. 선택하기 전에는 확정 버튼을 비활성화한다. 후보 선택만으로 돈·행동을 소비하지 않으며 기존 확정 단계에서 처리한다. 구매자 재제안 등으로 범위가 바뀌면 유효한 후보를 다시 선택한다.

HTML select/button/radio/checkbox의 키보드 접근성은 유지한다. 텍스트·숫자 입력칸, textarea, contenteditable, 텍스트 prompt를 추가하지 않는다. 보관·자동 저장·백업 형식과 게임 엔진의 기존 유효성 검사는 유지한다.

## 코드 책임

`app/amountChoices.ts`가 공개 정보로 후보를 만들고 금액을 정규화한다. `AmountChoice`가 선택 상태와 확정 버튼을 공통 렌더링한다. 엔진은 기존처럼 확정된 숫자를 받아 비용·원금·등록 가격·거래를 검증한다. 화면에 금액 입력을 새로 추가할 때는 이 선택 전용 정책을 우선 적용한다.
