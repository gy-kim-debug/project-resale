# 저장 슬롯

## 사용자 요청과 이번 적용

사용자는 앱 진입용 메인 화면과 저장 슬롯 도입 가능 여부를 확인하고, 새 게임에서 캐릭터 외형·닉네임을 설정하도록 요청했다. 기존 IndexedDB 저장소를 확장해 구현했다.

이번 구현 정책으로 슬롯은 3개를 제공한다. 슬롯 수는 사용자 확정 밸런스가 아니라 초기 UI/저장 정책이며 확장할 수 있다. 각 슬롯은 게임 상태, 캐릭터, 관심 매물, 선택한 시장, 우편 읽음 표시를 독립적으로 저장한다. 슬롯끼리 자산·도감·능력치를 공유하지 않는다. 새로 시작은 빈 슬롯에서만 가능하다. 사용 중인 슬롯을 만들기로 덮어쓸 수 없다.

## 자동 저장과 전환

행동·설정 변경은 현재 슬롯에 자동 저장한다. 저장 큐에 스냅샷과 슬롯 번호를 함께 캡처해 이후 다른 슬롯을 선택해도 이전 저장이 새 슬롯을 덮어쓰지 않는다. 슬롯 전환·메뉴 이동은 저장 큐가 끝난 후 실행한다. 행동 연출 중에는 전환하지 않는다. 저장에 실패하면 현재 게임에 남아 저장 재시도와 백업을 할 수 있게 한다.

메인 화면의 이어하기는 마지막 저장 시각이 가장 최근인 유효 슬롯을 연다. 다른 슬롯은 저장 슬롯 화면에서 고른다. 종료된 슬롯도 결과를 확인할 수 있으며, 자동 재시작하거나 부활시키지 않는다.

## 기존 저장 이전과 복구

IndexedDB `resale-game`의 기존 `saves` 저장소와 버전 2를 유지한다. 기존 `current`를 슬롯 1에 한 번 복사하며 원본은 복구용으로 보존한다. 이전 완료 표시와 복사는 하나의 readwrite 트랜잭션에서 처리한다. 프로필이 없는 이전 게임은 저장 내용을 다시 쓰지 않고 기본 캐릭터/플레이어 표시를 사용한다.

슬롯 키는 `slot:1`~`slot:3`, 시각은 `slot-time:1`~`slot-time:3`, 이전 완료 표시는 `slots-initialized`다. 기존 v1 관심 목록은 `legacy-v1`로 보존한다. 기존 v2 백업은 그대로 가져오고 내보낼 수 있다. 백업 가져오기는 사용자가 확인한 현재 슬롯만 교체한다.

손상된 슬롯은 비어 있다고 간주해 덮어쓰지 않는다. 해당 슬롯의 원본을 보존하고 오류를 표시하며, 다른 빈 슬롯에서 진행할 수 있다. 삭제는 슬롯 화면의 별도 확인을 거친다. 삭제한 슬롯은 옛 `current`에서 다시 이전하지 않는다. 동일 슬롯을 이미 사용 중인 경우 원자적인 생성 검사로 두 번째 생성 요청을 거부한다.

슬롯은 해당 브라우저/기기에 저장한다. 다른 기기에는 기존 JSON 백업으로 옮긴다. 클라우드 동기화·계정·백엔드·유료 저장은 도입하지 않는다.

## 새로고침 자동 복귀 — 사용자 요청

사용자는 게임 중 새로고침할 때마다 시작 화면으로 돌아가는 문제를 수정하도록 요청했다.

- 같은 브라우저 탭에서 플레이한 슬롯과 하단 메뉴를 `sessionStorage`의 `resale:resume`에 기록한다. 실제 게임·캐릭터·자산·행동·우편 읽음·시장 선택은 계속 IndexedDB 슬롯에서 읽는다. 게임 데이터를 이중 저장하지 않는다.
- 새로고침 시 해당 슬롯이 유효하면 시작 화면의 이어하기를 다시 누르지 않고 게임으로 복귀한다. 다른 슬롯의 저장 시각이 더 최근이어도 기록된 슬롯을 우선한다.
- 저장된 시작/상환/거래 대화의 위치와 선택은 기존 Game.story 상태로 이어진다. 경제 명령·납부·보상·시간을 다시 실행하지 않는다. 행동 연출 자체를 재생하지 않고 마지막 저장된 결과로 복귀한다.
- 하단 탭은 유지한다. 일반 상세 화면의 내부 뒤로가기 이력은 현재 탭의 기본 화면에서 새로 시작하며, 답변이 필요한 문의·정산·스토리는 기존 상태에 따라 표시한다.
- 설정에서 ‘시작 화면으로’를 직접 선택하면 저장 성공 후 메뉴 의도를 기록한다. 그 상태에서 새로고침해도 시작 화면을 유지한다. 저장 실패로 나가지 못했다면 게임 복귀 의도를 유지한다.
- 새 슬롯 생성·이어하기·백업 가져오기·명시적인 새 시작이 성공했을 때만 게임 복귀 의도를 기록한다. 하단 탭 이동도 해당 탭을 기록한다.
- 선택한 슬롯이 삭제됐거나 손상돼 읽을 수 없다면 시작 화면에서 오류와 슬롯을 확인하게 한다. 다른 슬롯을 자동으로 실행하거나 빈 슬롯을 새로 만들지 않는다.
- 구버전 앱에서 처음 새로고침해 복귀 기록이 없는 경우, 브라우저가 reload로 판단한 진입에 한해 가장 최근의 유효 저장으로 복귀한다. 일반 신규 진입은 기존 시작 화면을 유지한다.
- 잘못된 복귀 기록은 메뉴로 처리한다. sessionStorage 접근이 제한돼도 실제 플레이와 IndexedDB 저장은 막지 않으며, 이 경우 자동 복귀 대신 시작 화면에서 이어갈 수 있다.

복귀 의도의 파싱·안전한 브라우저 저장 접근은 `src/app/resumeSession.ts`, 슬롯 검증과 로드는 기존 저장소, 화면 복귀는 Zustand의 hydrate에서 담당한다. 슬롯 형식이나 IndexedDB 버전은 변경하지 않는다.
