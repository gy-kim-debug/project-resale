# 주간 이자와 미납 종료

## 사용자 확정

- 현금 0원 즉시 종료를 폐기한다. 주간 이자를 납부하지 못하면 게임 오버다.
- 원금은 납부일에 묶이지 않고 갚을 수 있다.
- 7일마다 납부 시점의 남은 원금 × 해당 주의 이자율을 납부해야 다음 진행이 가능하다. 매일 이자를 누적하거나 미납 이자를 원금에 더하지 않는다.
- 주가 지날수록 이율을 올린다. 사용자 예시는 1주차 0.001%, 2주차 0.003%, 3주차 0.005%다.
- 사용자가 확정한 시작 자본금은 500,000원이다.

## 예시를 적용한 초기 정책 — 조정 가능

주간 이율 = 0.001% + (주차 − 1) × 0.002%p. 상한은 아직 정하지 않고 현재는 같은 간격으로 계속 증가한다. 코드 설정은 `rules.ts`, 계산은 `domain/debt.ts`다.

| 주차 | 이율   | 원금 100억 원 유지 시 납부액 |
| ---- | ------ | ---------------------------- |
| 1    | 0.001% | 100,000원                    |
| 2    | 0.003% | 300,000원                    |
| 3    | 0.005% | 500,000원                    |
| 4    | 0.007% | 700,000원                    |
| 5    | 0.009% | 900,000원                    |

7·14·21일째의 세 번째 행동을 마치면 납부 절차로 전환한다. 표시 날짜는 다음 날짜지만, 해당 주 이율로 정산한다. 현금이 충분하면 필수 납부 화면을 열어 다른 행동·이동·흥정을 막는다. 부족하면 보유 물품이나 판매 중인 글이 있어도 즉시 종료한다. 현금을 자동으로 인출하지 않으며 전액 납부를 선택해야 진행한다.

납부는 추가 행동을 쓰지 않는다. 납부 완료 기록을 저장해 재접속·연타로 중복 납부하지 못한다. 정확한 납부액과 현금이 같으면 현금 0원으로 계속 진행할 수 있다.

원금 상환은 일반 진행에서 행동 1회다. 필수 납부 화면에서는 시간을 멈춘 채 원금 상환도 허용하며, 추가 행동 없이 낮아진 원금으로 납부액을 다시 계산한다. 이 때문에 현금이 부족해지면 종료한다. 원금·남은 과거 이자를 전부 정리하면 클리어를 우선한다. 주간 납부액은 원금을 줄이지 않는다. 원금 상환과 이자 납부 모두 누적 상환에 기록한다.

## 금액 계산

이율은 0.001% 단위의 정수 1·3·5…로 보관한다. 원화 계산은 BigInt 중간 연산으로 곱셈 정밀도를 지키고 원 단위 올림한다. 미납 전에는 예상액을 표시하고, 원금을 갚으면 즉시 갱신한다.

## 저장 전환

구 저장의 생존 수치는 삭제하고 현금·물품·채무·행동 예산은 보존한다. 기존 0원 저장도 주간 납부 기한 전에는 진행 가능하다. 새 게임에만 50만 원을 지급하며 기존 저장에 현금을 보충하지 않는다.

구 일일 이자 저장은 완료된 과거 주를 다시 청구하지 않고 현재 주부터 새 정책을 적용한다. 기존 미납 이자는 별도 잔액으로 유지하며 따로 납부하거나 다음 주간 납부에 함께 정산한다. 새 저장에는 마지막 납부 주차 `interestWeek`를 보관한다. 이미 종료된 저장은 되살리지 않는다.

## 후속 밸런스 검토

현재 설정은 사용자의 예시를 플레이 가능한 형태로 옮긴 첫 정책이다. 시작금·이율 증가 폭·상한은 추가 조정 가능하다. 이전 10만 원 시작 테스트에서 단순 자동 거래 전략은 2–3번째 납부에 실패했으며, 이 결과만으로 모든 전략의 클리어 가능성이나 적정 난도를 판단하지 않는다.

50만 원 시작으로 같은 단순 자동 거래 전략을 다시 실행한 3개 시드는 각각 11·5·4번째 납부에서 실패했다. 초기 현금 변경의 검증 기록이며, 최적 전략의 생존 기간이나 적정 난도를 뜻하지 않는다.
