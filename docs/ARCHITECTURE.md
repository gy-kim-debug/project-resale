# 아키텍처

## 현재 구성

React + TypeScript + Vite, Tailwind CSS v4, Zustand, idb 기반 IndexedDB. 네이티브 의존성과 서버는 없다.

| 위치             | 책임                                         |
| ---------------- | -------------------------------------------- |
| src/App.tsx      | 5개 탭과 활동 내부 화면 조립 및 탐색         |
| src/components   | 재사용 UI, 플레이어 상태 표시                |
| src/app/store.ts | Zustand의 탐색 상태·관심 매물·저장 오류 처리 |
| src/content      | 고정 매물과 카테고리 콘텐츠                  |
| src/domain       | React와 무관한 타입·시작 상태·원화 표시 함수 |
| src/storage      | SaveRepository 인터페이스와 IndexedDB 구현   |
| docs             | 요구사항, 미확정 규칙, 개발 순서             |
| work             | 커밋 제외 임시 검증 자료                     |

## 설계 원칙

UI에서 이자·시간·확률·거래·생존 계산을 하지 않는다. 추후 domain에 입력 상태와 명시적 시간·난수를 받는 순수 함수를 추가하고 Zustand는 결과를 반영한다. 콘텐츠와 실행 로직을 분리하며 불필요한 프레임워크나 범용 엔진은 만들지 않는다.

금액은 원 단위 정수 number를 사용한다. 수백억 원은 Number.MAX_SAFE_INTEGER(9,007,199,254,740,991) 범위 안에서 정확하다. 현재 표시 함수가 음수·소수·안전 정수 초과를 거부한다. 향후 모든 금액 연산 결과도 검증하고 이자는 정수 비율과 명시적 반올림 정책으로 구현한다. 안전 범위를 넘겨야 할 경우 bigint와 문자열 직렬화로 마이그레이션한다. 소수 금액 계산과 비트 연산은 사용하지 않는다.

## 저장

현재 version 1 저장은 관심 매물 ID만 포함한다. 초기 로드 중 관심 변경을 비활성화하여 덮어쓰기를 막고, 저장을 직렬화하여 쓰기 순서를 유지한다. 저장 데이터 형상을 확인하고 실패 시 임시 메모리 상태로 계속 사용하면서 안내한다. 추후 네이티브 구현을 SaveRepository로 교체할 수 있다. 게임 저장 스키마와 마이그레이션, 다중 탭 충돌 정책은 다음 단계에서 설계한다.

## 모바일과 오프라인

뷰포트, safe-area, 100dvh, 최소 44px 버튼, 하단 고정 메뉴 공간, 키보드 포커스를 고려했다. 외부 이미지·폰트·API 요청은 없다. 설치 후 네트워크 없이 실행하는 PWA 서비스 워커는 이번 범위에 포함하지 않았다. 현재는 이미 로드된 화면을 네트워크 없이 조작할 수 있으며 새로고침·첫 실행의 오프라인 보장은 후속 과제다.

생존 상태(PlayerStatus)는 App의 공통 sticky 헤더에서 한 번 렌더링한다. 탭 이동과 장터 상세 탐색·스크롤 중에도 포만감·피로도·체력을 확인할 수 있다.

## 탐색 상태

`Tab`은 활동·내 정보·보관함·상점·채무 5개만 허용한다. `activity`는 장터·무료나눔·아르바이트·물건 수집·매각처·식사·수면·치료 또는 null이다. `openActivity`는 활동 탭에서 내부 화면을 열고, `setTab`은 내부 화면과 선택 매물을 초기화한다. 장터와 생존 행동은 하단 독립 탭이 아니다. 보관함의 관심 매물에서는 활동의 장터 상세로 이동한다. `ActivityScreen`이 활동 허브와 행동 상세를, `MarketScreen`이 장터를, `UtilityScreens`가 나머지 4개 탭을 담당한다.

## 화면 목업 상태 (2026-10-19)

`src/app/previewStore.ts`는 메모리 전용 목업 현금·물품·판매 글·문의와 결과 안내를 관리한다. `src/content/preview.ts`의 데이터는 밸런스와 분리된 테스트 예시다. 기존 `store.ts`는 탐색과 관심 저장만 담당한다. `TradeScreens.tsx`는 구매 절차·보관 물품 상세·구매 문의·매각처를 구성한다. App은 문의 대기 상태일 때 일반 탐색 대신 응답 화면을 표시한다.

이 상태 전이는 실제 게임 엔진이 아니다. 추후 도메인 규칙을 구현할 때 시간·생존·랜덤 결과 계산을 이 목업에 추가하지 않고, 확정된 설계에 따라 별도 순수 함수로 대체한다. 목업 범위·미구현 항목·임시 UI 제한은 [화면 토대](SCREEN_FOUNDATION.md)에 기록한다. `Player`의 기존 `hunger/health` 필드명은 호환을 유지하되 현재 UI 의미는 포만감/체력이며, 실제 도메인 구현 때 명칭과 스키마를 정리한다.
