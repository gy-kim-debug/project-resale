# 게임 상세 설계 기준서

상태: **논의용 초안 v0.1 — 구현 명세 확정 전**  
작성일: 2026-10-16 (KST)

이 문서는 게임 규칙을 결정하기 위한 기준서다. 기존 화면은 탐색과 분위기를 확인한 목업이며, 화면에 보이는 숫자·문구·버튼이 게임 규칙을 확정하지 않는다. 당분간 신규 화면 개발보다 이 문서의 미정 항목을 먼저 논의한다.

## 1. 문서 사용법

- **확정**: 사용자가 정한 요구사항. 구현과 후속 제안은 이를 따른다.
- **미정**: 논의되지 않았거나 결정이 필요한 사항. 임의 구현하지 않는다.
- **제안**: 비교·검토를 위한 개발 파트너의 안. 사용자 결정 전에는 규칙이 아니다.
- **목업**: 이미 화면에 있으나 게임 규칙으로 확정되지 않은 값이나 기능.

규칙은 이 문서에서 확정하고, 수치 밸런스는 별도로 검토한다. 구현에 필요한 선행 규칙이 미정이면 해당 기능의 설계를 먼저 진행한다. 모든 미래 시스템을 한꺼번에 확정할 필요는 없으며, 최소 플레이 구간에 필요한 규칙부터 정한다.

## 2. 게임의 목표와 경계 [확정]

현금 0원과 원금 100억 원에서 시작한다. 중고 물품을 매입하고, 필요하면 감정·수리한 뒤 재판매하며 생존한다. 원금과 발생 이자를 모두 갚으면 클리어한다.

핵심은 물건의 불확실한 가치를 판단하면서 자금·시간·생존을 함께 관리하는 선택이다. 대박과 손실, 다시 무일푼이 되는 상황이 가능해야 한다. 손실을 단순히 무작위로 강요하기보다 위험을 살피거나 감수할 선택을 제공한다.

- 사망하면 게임이 종료된다. 회차 표시, 직업 상태, 회차 간 계승·영구 성장 시스템을 두지 않는다.
- 배고픔·피로·건강은 실제 물품 가치나 확률적 거래 결과를 직접 보정하지 않는다.
- 거래 행동을 모두 고정 순서로 강제하지 않는다. 다른 매물 탐색과 생존 활동을 오갈 수 있어야 한다.
- 모바일 웹 우선, 싱글 플레이, 초기 백엔드 없음. 오프라인 실행을 지향한다.
- 현실 결제, 인증 시스템, 네이티브 프로젝트 생성은 현재 게임 구현 범위 밖이다. 개발용 비공개 배포 로그인과 게임 내부 인증은 별개다.

## 3. 플레이 구조와 화면의 책임 [확정]

| 영역      | 책임                                                               | 미정 사항                             |
| --------- | ------------------------------------------------------------------ | ------------------------------------- |
| 공통 헤더 | 배고픔·피로·건강을 모든 화면에 표시                                | 수치 범위·의미·초기값, 추가 표시 정보 |
| 활동      | 대부분의 플레이가 시작되는 허브. 장터·식사·수면·숙박을 선택해 진입 | 추가 활동, 각 행동의 비용·시간·조건   |
| 내 정보   | 현재 플레이어 정보 확인                                            | 표시할 추가 항목과 상세 지표          |
| 보관함    | 보유 물품과 관심 매물 확인                                         | 용량, 보관 비용, 정렬, 처분 방식      |
| 상점      | 독립된 하단 탭                                                     | 역할·품목·가격·이용 방식 전체         |
| 채무      | 원금·발생 이자 확인, 일부 상환, 전액 상환 목표                     | 계산·정산·상환 세부 규칙              |

장터는 하단 독립 탭이 아니라 활동 내부의 중고거래 앱이다. 장터를 열어도 활동 탭에 속한다. 어두운 생존 화면과 친숙한 중고거래 앱의 대비는 유지한다. 세부 배치는 게임 규칙 결정 후 다시 설계한다.

## 4. 플레이어 상태 [확정 / 미정 구분]

| 상태           | 확정된 의미                           | 먼저 정할 규칙                             |
| -------------- | ------------------------------------- | ------------------------------------------ |
| 현금           | 즉시 사용할 수 있는 원화, 시작 0원    | 음수 허용 여부, 자금 부족 시 처리          |
| 채무 원금      | 시작 10,000,000,000원                 | 추가 채무 허용 여부는 미정                 |
| 발생 이자      | 원금과 별도 관리                      | 시작 이자, 이자율·정산·반올림              |
| 배고픔         | 시간과 식사 관련 생존 지표            | 높을수록 배고픈지, 범위·초기값·변화율      |
| 피로           | 시간과 휴식 관련 생존 지표            | 범위·초기값·변화율·제한 조건               |
| 건강           | 생존과 사망 관련 지표                 | 범위·초기값·감소·회복·사망 판정            |
| 게임 시간      | 행동할 때만 진행. 읽기·미접속 중 정지 | 시간을 쓰는 행동, 소요 시간·단위·시작 시각 |
| 보유 물품      | 매입·보관·처리·판매 대상              | 보유 한도, 동시 작업·판매 가능 여부        |
| 거래·선택 기록 | 조건부·연속 이벤트에 사용할 정보      | 기록 범위와 유지 정책                      |

현금 0원·원금 100억 원 외의 초기값은 미정이다. 화면의 배고픔 20, 피로 15, 건강 100, DAY 1 09:00, 발생 이자 0원은 목업이다.

## 5. 시간과 행동 [방식 확정 / 행동별 규칙 미정]

**확정:** 행동할 때만 게임 시간이 진행한다. 글을 읽거나 판단하는 동안, 앱을 꺼두거나 접속하지 않는 동안에는 멈춘다. 현실에서 기다리는 것만으로 생존 상태·이자·판매 대기·이벤트 시간을 진행시키지 않는다.

단순 화면 열람과 실제 게임 행동은 구분한다. 장터 갱신·검수·협상 등을 ‘시간을 쓰는 행동’으로 볼지, 각 행동이 몇 분을 쓰는지와 행동 확정 시점은 아직 미정이다. 판매·수리의 대기가 생기면 게임 시간의 진행에 따라 처리하는 방향으로 세부 규칙을 정한다.

이 방식은 생존, 판매 대기, 수리, 이자, 이벤트의 공통 기준이다. 앱을 꺼둔 동안의 경과 시간을 뒤늦게 정산하지 않는다. 오프라인에서 앱을 실행할 수 있게 하는 기능과 게임 시간의 미접속 중 정지는 별개다.

행동마다 다음 항목을 채운 뒤 구현한다.

| 행동           | 진입점                | 결정할 내용                                        |
| -------------- | --------------------- | -------------------------------------------------- |
| 매물 탐색·갱신 | 활동 → 장터           | 단순 열람도 시간을 쓰는지, 재생성 조건과 갱신 비용 |
| 정보 확인·협상 | 장터 → 상세           | 얻는 정보, 비용·시간, 취소·실패 시 처리            |
| 매입·운반      | 장터 → 상세           | 결제 시점, 소유권·인벤토리 반영, 운반 방식         |
| 감정·수리      | 보유품 관련 경로 미정 | 대상·비용·시간·정확도·실패 효과                    |
| 판매 등록·대기 | 보유품 관련 경로 미정 | 가격 설정, 대기, 판매 성사·취소·환불               |
| 식사·수면·숙박 | 활동 → 해당 행동      | 이용 조건·비용·시간·상태 변화, 무자금 시 선택지    |
| 채무 상환      | 채무                  | 금액 입력 범위, 상환 순서, 시간 비용               |

## 6. 현금 0원에서 첫 수익까지 [미정]

매입 자금과 식비가 모두 없는 상태에서 반드시 가능한 첫 행동이 필요하다. 아직 시작 자금 확보 방법은 확정하지 않았다.

**비교할 제안:** 무료 나눔을 찾아 판매하기 / 버려진 물건을 수집해 판매하기. 어느 쪽도 확정하지 않는다. 기존 무료 나눔 목업을 곧바로 공식 시작 루트로 취급하지 않는다.

결정할 질문:

- 처음 가능한 행동은 무엇이며, 어떤 정보를 보고 선택하는가?
- 첫 물건 확보·운반·보관에 돈이나 시간이 필요한가?
- 현금 0원일 때 먹고 잘 수 있는가? 가능하다면 비용 대신 무엇을 감수하는가?
- 첫 판매는 반드시 가능한가, 손실·실패할 수도 있는가?
- 진행 중 다시 현금과 물품이 모두 없어져도 같은 경로를 이용할 수 있는가?

## 7. 물품과 거래 [부분 확정]

### 물품 정보

**확정:** 카테고리, 판매자 제시 가격, 실제 가치, 상태·숨은 결함을 구분한다. 매물에 보이는 정보와 실체가 다를 수 있으며 희귀품·특별 매물을 확장할 수 있어야 한다.

**제안:** 정보는 ‘판매자의 주장 / 확인된 사실 / 미확인 정보’로 구분한다. 사용자가 확인한 정보의 출처를 보존하면 가품·고장 결과를 이해하기 쉽다. 구체적인 공개 방식은 미정이다.

**미정:** 실제 가치를 생성 시 고정할지, 상태와 시세에 따라 어떻게 갱신할지, 판매자 설명의 신뢰도, 결함 확인 방법, 감정 정확도, 희귀품 발견 조건.

### 거래 단계별 결정

| 단계      | 확정 방향                      | 미정 규칙                                          |
| --------- | ------------------------------ | -------------------------------------------------- |
| 매물 등장 | 다양한 일반·특별 매물          | 생성·소멸·갱신 주기, 매물 수·가격 분포             |
| 상세 확인 | 위험을 판단할 정보와 선택 제공 | 무료 정보, 추가 확인·검수 비용과 결과              |
| 협상      | 구매 여부와 가격 협상 선택     | 제시 가능 범위, 시도 횟수, 거절·철회               |
| 매입      | 현금과 물품 소유 상태 변경     | 구매 확정 시점, 자금·보관 한도 확인 순서           |
| 감정·수리 | 매입 후 선택 가능한 처리       | 비용·시간, 가치 공개 범위, 수리 성공·실패          |
| 재판매    | 판매 가격을 정하고 판매 진행   | 즉시 판매/대기 판매, 가격과 수요의 관계, 판매 실패 |
| 사후 문제 | 파손·가품·배송·환불 사건 고려  | 발생 조건·책임·금전 처리·중복 방지                 |

**불변 조건 [확정]:** 생존 수치를 입력으로 실제 가치나 거래 확률을 직접 높이거나 낮추지 않는다. 행동 제한·시간 비용 같은 생존 영향의 구체적인 범위는 별도 논의한다.

## 8. 생존과 종료 [부분 확정]

시간이 흐르면 배고픔과 피로가 변하고, 악화되면 건강 감소나 행동 제한이 발생할 수 있다. 식사·수면·숙박이 생존 활동이다. **사망하면 게임이 종료된다.**

미정 사항:

- 각 수치의 의미·범위·초기값·변화율, 경고 구간과 회복 방법.
- 건강 악화와 사망을 판정하는 조건. 건강 0을 사망 조건으로 아직 확정하지 않는다.
- 어떤 행동이 제한되며, 제한된 상태에서 회복할 경로가 있는지.
- 현금 0원은 즉시 종료인지 아닌지. 파산은 사망과 별개로 종료 조건인지.
- 동일한 행동에서 사망과 전액 상환 조건을 함께 충족했을 때 판정 순서.
- 사망 시 진행 저장을 어떻게 처리할지. 종료 화면·새 게임 시작 정책도 별도 논의한다.

이번 문서 작업에서 사망 엔진이나 종료 화면을 구현하지 않는다.

## 9. 채무와 장기 경제 [부분 확정]

**확정:** 초기 원금 100억 원. 발생 이자와 구분하고 자유로운 일부 상환을 지원한다. 원금과 발생 이자를 모두 갚으면 클리어한다. 원화는 정수로 정확하게 처리한다.

**미정:** 이자율, 단리·복리, 계산 대상 잔액, 정산 주기·시점, 소수 원화 처리, 원금·이자 상환 우선순위, 입력 가능한 상환액, 초과 상환·환불, 독촉 사건과 제재.

행동 기반 시간에서의 행동별 소요 시간과 첫 거래의 수익·비용 구조를 정한 뒤 이자를 논의한다. 작은 거래로 시작해 100억 원까지 도달할 성장 경로와, 생활비·이자 때문에 수익이 무의미해지지 않는지 함께 검토해야 한다.

**검토 제안:** 이자율부터 정하지 않고 첫 수익 → 안정적인 거래 → 더 큰 물품·대량 거래 → 최종 상환의 도달 가능성을 표로 검증한다. 금액·확률·단계별 수익은 아직 정하지 않는다.

## 10. 시장·이벤트·관계 [부분 확정]

급처·이사·폐업·미확인 창고·희귀품·대량 거래, 물품 파손·수리 실패·가품·배송·시세 폭락·환불, 카테고리 수요와 시장 변화, 단골·감정사·수리 전문가·경쟁자·거래처, 생활비·건강·채권자 사건을 고려한다.

**확정:** 순수 무작위 외에도 시간·자산·보유품·거래 이력·이전 선택을 조건으로 사용할 수 있어야 하며 연속 사건을 지원한다.

**미정:** 첫 구현 이벤트 목록, 발생률·평가 시점·우선순위·동시 발생 한도, 선택 결과, 재발 제한, 후속 사건 조건, 해결 불가 사건 처리.

**이벤트 설계 양식 [제안]:** 발동 조건 / 알려주는 정보 / 선택지 / 각 비용·시간·확정 효과·확률 효과 / 후속 사건 / 종료 조건. 실제 사건 내용과 수치는 승인 후 채운다.

## 11. 보관함·상점·저장 [미정 중심]

- 보관함: 무제한인지, 부피·무게·수량 제한인지, 보관료와 파손·분실이 있는지, 판매 중 물품도 공간을 쓰는지, 버리기·처분이 가능한지.
- 상점: 무엇을 파는 곳인지부터 결정한다. 생존품·도구 등은 가능한 제안일 뿐 확정하지 않는다. 현실 결제 상점으로 가정하지 않는다. 장터와 역할이 겹치지 않아야 한다.
- 저장: 저장 시점·슬롯·버전 변경·사망 후 처리, 판매 대기·랜덤 결과의 재접속 처리, 앱 종료 중 시간은 멈추며, 행동 도중 종료했을 때의 저장·재개 방식은 결정해야 한다.
- 현재 구현은 관심 매물 ID만 저장한다. 배포 사이트 로그인은 기기 간 진행 데이터 동기화를 뜻하지 않는다.

## 13. 첫 플레이 검증 시나리오 [제안]

1. 현금 0원·원금 100억 원으로 시작한다. 다음에 할 수 있는 행동을 이해한다.
2. D02에서 정한 경로로 첫 물건을 얻고, 확인한 정보와 감수한 위험을 구분한다.
3. 판매를 통해 첫 수익을 얻거나 실패 결과를 이해한다. 실패 시 다음 선택이 무엇인지 확인한다.
4. 시간·생존 규칙에 따라 먹거나 쉬는 선택을 경험한다.
5. 자금이 있을 때 일부 상환하고 원금·이자의 변화를 확인한다.
6. 정해진 저장·재접속 규칙대로 진행을 복원한다.
7. 사망·전액 상환 경계는 별도 검증 상태로 확인한다. 첫 거래만으로 100억 상환을 가정하지 않는다.

아직 미정인 규칙 때문에 이 시나리오를 실행 가능한 완성 명세로 취급하지 않는다.
