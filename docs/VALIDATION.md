## 초기 실패 원인과 해결

기본 명령 실행 샌드박스에서 지정 프록시 `proxy:8080`으로의 TCP 연결이 `EPERM`으로 차단되었다. DNS는 정상 해석됐고 npm registry 설정과 허용 호스트도 정상이었다. curl과 npm 모두 실패했으며 오프라인 캐시와 대체 로컬 도구가 없어 설치 없이 진행할 수 없었다.

명령 실행에 네트워크 권한을 명시하자 동일한 프록시와 registry로 npm ping이 성공했고 의존성 설치가 완료됐다. 프록시 우회나 TLS 검증 해제는 하지 않았다. 미리보기 서버의 listen도 기본 샌드박스에서 EPERM이 발생했으나 같은 권한으로 실행에 성공했다. 이전의 단순 프록시 장애 설명은 불충분했고 명령 실행 권한 문제로 원인을 좁혔다. 추가로 기본 샌드박스의 오프라인 npm ci에서도 esbuild 설치 검증의 spawnSync EPERM이 발생했으며, 동일하게 네트워크 권한을 명시한 실행에서는 오프라인 재설치와 빌드가 통과했다.

- 매물 5개 노출, 카테고리 필터, 목록과 상세 이동.

## 활동 중심 5개 탭 재구성 (2026-10-16 KST)

회차·직업 표시를 제거하고 활동 / 내 정보 / 보관함 / 상점 / 채무 순서로 변경했다. 장터·식사·수면·숙박은 활동 내부 화면으로 이동한다. 사망하면 게임이 종료되는 기획으로 문서를 정리했으며 사망 판정 엔진은 아직 구현하지 않았다.

Chromium 320x844, 375x667, 390x844, 430x932에서 5개 메뉴 순서, 하위 활동 진입·복귀 및 활동 탭 선택 유지, 내 정보→채무, 카테고리 필터, 관심 매물 저장·새로고침 복원과 보관함→활동 장터 상세 이동, 상점 준비 상태, 고정 생존 헤더, 화면 넘침·하단 메뉴 가림·콘솔 오류 없음을 확인했다. TypeScript·ESLint·포맷·프로덕션 빌드 통과.

## 문서 기반 화면 토대 (2026-10-19)

확정 문서와 화면 대응은 [화면 토대](SCREEN_FOUNDATION.md)에 정리했다. 기존 `src/styles.css`는 수정하지 않았다. TypeScript·ESLint·Prettier·프로덕션 빌드·diff 공백 검사를 통과했다.

`python3 scripts/verify-screens.py`로 프로덕션 preview를 Chromium 320x844, 375x667, 390x844, 430x932에서 검증했다.

- 하단 5개 메뉴, 공통 포만감·체력·피로도 표시, 각 활동 진입, 가로 넘침 없음.
- 무료나눔 글 있는/없는 상황, 수령 후 보관함 이동, 가치 별도 확인.
- 안전 정수 범위를 벗어나는 판매 가격 거부, 등록 후 가격 입력 제거.
- 장터 등록 물품의 매각 차단, 복수 구매 문의 표시, 응답 전 모든 메뉴·홈 이동 차단.
- 파토 시 판매 글·문의 전체 종료, 새 가격 재등록, 거절 후 예시 재제안, 수락 후 목업 물품/대금 교환.
- 매물 카테고리, 관심 저장, 구매 전 확인 실행 보류, 선택형 네고·구매·중복 수령 방지, 목업 현금 차감.
- 매각처 방문 전 견적 비노출, 방문 후 고정 가격 판매.
- 수집 반복·보관 용량 초과 획득 차단, 물품 버리기 확인 후 공간 확보.
- 아르바이트·무료 급식·수면의 확인/결과 화면, 치료·상점 미정 안내, 채무 입력 확인.

- 모든 크기에서 pageerror·console error 없음. 320px 스크린샷도 직접 확인했다.

이 검증은 화면·메모리 목업 상태 전이 대상이다. 시간·생존·확률·경제 밸런스·이자 계산 검증이 아니다. 실제 폰·Safari/WebKit·가상 키보드·화면 읽기 도구 검증은 남아 있다. 스크립트는 Python Playwright와 시스템 Chromium이 설치된 환경에서 재실행할 수 있다.

사용자 선택으로 시간 표시와 시간 비례 진행을 하루 3행동으로 변경했다. 주요 행동은 종류와 관계없이 1회, 세 번째 행동 후 다음 날 3회를 지급한다. 수면·피로도 소진은 남은 행동을 포기하고 하루를 마무리한다. 이동·흥정·파토·물품 버리기·제안 거절은 예산을 소모하지 않는다. 헤더와 행동 연출에 날짜·남은 횟수를 표시하고 기록의 시각 표시는 제거했다.

생존은 행동당 기본 포만감/피로도 12와 작업별 추가 소모로 계산한다. 무거운 창고 일은 추가 피로도 42여서 연속 두 번이면 하루를 일찍 끝낼 수 있다. 식사/치료 회복은 행동 기본 소모 후, 하루 종료의 포만감 -18 전에 적용한다. 실제 가치·거래 확률은 생존 수치로 보정하지 않는다. 이자·시장·게시판은 하루 경계를 한 번만 정산한다.

기존 v2 저장은 동일 날짜·새 행동 3회로 한 번 전환하고 현금·채무·생존 수치·물품·매입가·채팅·난수는 유지한다. 기한은 행동 눈금으로 올림하며 유효한 기존 견적은 행동 2회로 이어 간다. `timeMode` 표식으로 이후 재접속 시 예산이 리셋되지 않게 한다. 새 진행 눈금이 손상된 데이터는 덮어쓰지 않고 거부한다.

타입·ESLint·포맷·프로덕션 빌드 통과. 테스트 45개 통과: 세 번째 행동의 정확한 다음 날 전환, 수면/피로도 조기 종료, 세 번째 식사의 회복/밤 순서, 무료 행동 예산 보존, 하루 경계 이자 중복 방지, 이전 저장 전환의 순수성·멱등성·자원/거래 보존, 기존 거래/생존 규칙 포함. 공개 가격과 구매 후 확인 정보만 쓰는 3개 시드 장기 플레이 모두 채무 완납했다.

Chromium 320/375/390/430px에서 하루 예산·조기 종료·시계 제거·기존 저장 전환/첫 행동 저장/재접속, 실제 전체 거래·식사·채무·사망·완납·백업·오프라인을 검증했다. 행동 연출·입력 잠금·연출 중 새로고침·동작 줄이기, 구매/판매 흥정·파토 후 글 유지·무료 이동·보관함 비교·우편함/설정·큰 금액도 네 크기에서 통과했다. 저장 손상 보존·구버전 보관·백업 복구·저장소 차단 검증도 통과했다. 320px·430px 홈 스크린샷을 확인했다. 실제 기기·Safari 검증은 별도다.

## 체력·피로도 삭제와 현금 소진 종료 — 당시 검토 기록

> 아래 내용은 이후 사용자 결정으로 대체됐다. 현재는 10만 원 시작·현금 0원 진행 가능·주간 이자 미납 종료다.

- 체력·피로도·회복 활동 및 계산을 제거하고 상단에 공통 정수 계산의 하루 이자를 표시했다. 기존 첫 3일 이자 유예는 유지한다. 이전 저장의 생존 수치는 정규화 시 삭제한다.

## 주차별 이율 상승과 주간 필수 납부 — 현재 구현

- 시작금 100,000원. 포만감·체력·피로도·식사·수면·치료는 삭제하고 하루 3행동을 유지했다. 현금 0원 즉시 종료는 폐기했다.
- 매 7일 종료 후 주간 이자를 납부해야 진행한다. 이율은 사용자 예시를 따라 주 0.001%에서 매주 0.002%p 증가한다. 납부 시 남은 원금을 기준으로 원 단위 올림하며 BigInt 중간 연산으로 정밀도를 지킨다. 원금 상환과 이자 납부를 분리했다.
- 현금 부족은 보유품과 무관하게 미납 종료. 충분하면 납부 창을 강제하고 이동·흥정·다른 행동을 막는다. 납부는 행동 소모 없음이며, 마지막 주차를 저장해 중복 납부를 막는다. 납부 화면에서 원금을 줄이면 즉시 이자를 다시 계산한다. 전액 완납은 클리어가 우선이다.
- 기존 저장의 자산·진행은 유지하고 구 생존 필드만 제거한다. 기존 일일 이자 잔액은 보존하고 과거 주를 소급 청구하지 않는다. 이전 0원 저장도 납부 기한 전에는 진행할 수 있다.
- 타입 검사·ESLint·Prettier·프로덕션 빌드·변경 공백 검사 통과. 엔진/상태 테스트 53개 통과. 주간 경계·진행 잠금·전액/중복 납부·납부 후 0원 진행·이율 상승·원금 재계산·미납 종료·저장 복원·이전 저장 전환 포함.

## 가치 확인·수리의 행동 소모 제거

- 사용자 확정에 따라 `check`·`repair`에서 시간 진행을 제거했다. 비용·감정 정보 공개·수리 성공/실패·능력치 경험·물품당 1회 제한은 유지한다. 날짜·남은 행동·매물/판매/견적/사건 기한과 주간 납부 시점은 진행하지 않으며 새 문의·사건도 생성하지 않는다. 필수 문의 응답·주간 납부 잠금은 유지한다.

## 매물 해시태그와 확률적인 사실·거래 효과

- 사용자가 부동산 다음 시장으로 고가 경매시장을 선택했다. 구현 전에 `docs/design/markets/AUCTION.md`에 확정 방향과 개발자 초기 정책을 기록하고 이전 후보 비교를 과거 기록으로 표시했다. 시작가 10억–100억 원·희귀 미술품/보석/골동품 6종·시장당 8개를 적용했다. 비행기 시장은 계속 제거 상태다.
- 일반 네고 대신 공개 입찰과 경쟁자 응찰 대화를 제공한다. 경쟁 한도는 시작 시 저장하며 실제 가치와 독립이다. 입찰 간격은 시작가 5%를 100만 원 단위로 올림하며 경쟁 한도 110–145% 미만에서 최대 6회 입찰로 결론 난다. 입찰·포기는 행동/현금/난수 소모 없이 저장하고, 낙찰 후 확인·결제 시에만 정확한 낙찰가 차감·물품 이전·행동 1회를 적용한다.
- 미낙찰 즉시 구매·일반 흥정 우회·과거 입찰 선택지·부족한 현금·포기 후 재입찰·결제 중복을 거절한다. 결제 시 현금과 보관 공간을 다시 확인하고 주간 납부·필수 문의 잠금을 유지한다. 구매 후 가치/진위 확인은 계속 행동 소모 없음이며 보유 경매품은 기존 정가 위탁 판매·수집품 매입처로 재판매한다. 플레이어 출품 경쟁 입찰은 추가하지 않았다.
- 경매의 종류/특징 태그와 85% 사실 확률을 유지하고 판매자 네고 태그는 제외했다. 구매 전 실제 가치·진위·경쟁 한도는 숨긴다. 현재가·진행 상태·대화·경쟁 한도를 백업하고 잘못된 금액·간격·한도·라운드·상태·대화를 거절한다. 공개 품목에 따른 도트도 추가했다.
- TypeScript·ESLint·Prettier·프로덕션 빌드·변경 공백·문서 링크 검사 통과. 엔진/상태 테스트 79개 통과: 여러 시드의 무료 입찰·한도/라운드 종료·재접속 스냅샷·낙찰가 정확 결제·중복 거절, 현금/공간/주간 잠금·포기·만료·잘못된 백업 검증과 다른 시장의 기존 거래 흐름을 확인했다. 자동 거래 전략도 경매에 입찰하도록 갱신했다.
- Chromium 모바일 320/375/390/430px에서 `scripts/verify-auction.py` 통과: 부족한 자금의 버튼 잠금·입찰 대화·재접속·오프라인 입찰/결제·정확한 낙찰 매입가·행동 1회·0행동 감정·위탁 판매 경로·백업·포기·가로 넘침 없음을 확인했다. 실제 기기·Safari·경매 수익 밸런스 검증은 별도다.

- `scripts/verify-markets.py`도 같은 4개 모바일 크기에서 통과했다. 활성 6개 시장의 목록/가격/무료 이동/선택 복원·개별 갱신·일반 자산 구매/검증/백업과 이전 항공기 보유 저장의 호환을 확인했다.

## 활동에서 각 시장으로 직접 진입

- 사용자 지적에 따라 시장 진입 구조를 수정했다. 활동의 시장 영역에 장터·컴퓨터시장·악기시장·중고차시장·부동산 시장·고가 경매시장 독립 버튼을 배치하고 내부 시장 선택 패널을 제거했다. 매각처는 별도 매각 영역의 보유품 고정 제시가 판매 경로로 유지했다.
- `Route.marketId`로 시장을 명시하고 목록·상세·뒤로 가기·화면 제목을 해당 시장으로 고정한다. 마지막 방문 메타데이터가 장터 버튼을 다른 시장으로 보내지 않게 했다. 시장 이동은 계속 행동·현금·난수·매물 갱신을 소모하지 않는다. 일반 5개 시장은 공통 장터형 목록/판매자 채팅/흥정/구매, 고가 경매만 입찰을 사용한다.
- 타입 검사·ESLint·Prettier·프로덕션 빌드·변경 공백 검사 통과. 기존 엔진/상태 테스트 79개 통과. 경제·매물 생성·저장 스키마는 바꾸지 않았다.
- Chromium 모바일 320/375/390/430px에서 `scripts/verify-markets.py` 통과: 활동의 직접 버튼 6개·중간 선택 화면 부재·시장별 제목/목록·상세 왕복·무료 이동·일반 5곳의 채팅·경매 전용 입찰·매각처 분리·개별 매물 탐색·컴퓨터시장 흥정/구매/0행동 검증·가로 넘침 없음을 확인했다.
- 같은 4개 크기에서 `scripts/verify-auction.py`도 새 고가 경매 바로가기로 입찰·재접속·오프라인·낙찰 결제·감정·백업·포기를 통과했다. 실제 기기·Safari 검증은 별도다.
