# 로드맵

> 이전 기획의 참고 자료입니다. 현재 설계는 사용자가 처음부터 결정해 작성하는 [게임 설계서](GAME_DESIGN.md)를 따릅니다. 아래 내용은 새 설계에 자동 반영하지 않습니다.

아래 순서는 제안이며 세부 게임 규칙을 확정하지 않는다. 현재 신규 화면 개발은 보류한다.

0. **상세 규칙 정리 (현재 우선순위)**: [게임 상세 설계 기준서](GAME_DESIGN.md)의 D01~D06부터 논의한다. 행동별 소요 시간(행동 기반 시간은 확정) → 첫 수익·최소 생존 경로 → 최소 거래 → 생존·사망 → 채무 → 저장의 순서로 규칙을 정의한다. 해당 기능에 필요한 규칙이 정리되면 순수 로직과 검증을 먼저 구현하고 화면에 연결한다.

1. **초기 기반 (이번 작업)**: React/TS/Vite, Tailwind, Zustand, 저장 인터페이스, 모바일 게시판·상세 및 탐색, 문서·정적 검증.
2. **최소 거래 루프**: 정보와 위험을 확인하는 선택, 고정 데이터 매입→인벤토리→재판매, 안전한 원화 연산과 순수 함수 테스트. 50만 원 시작과 주간 이자 납부도 함께 설계한다. 가장 먼저 게임의 핵심 재미를 검증한다.
3. **시간·생존·채무**: 시간 단위, 행동 비용, 생존 한계, 이자·반올림·상환 규칙을 결정한 뒤 독립 함수로 구현하고 경계값을 검증한다.
4. **생성·경제**: 시드 난수, 가치·결함·정보 공개, 협상·수리·감정, 시장 변화. 재현 가능한 테스트로 생존 수치와 확률의 독립성을 확인한다.
5. **이벤트·게임 종료**: 조건부/연속 이벤트, 결과 기록, 사망 시 종료와 채무 전액 상환 클리어. 회차·직업·계승·영구 성장은 구현하지 않는다.
6. **저장·오프라인 강화**: 게임 진행 상태 저장, 버전 마이그레이션, 가져오기·내보내기, PWA 캐시·업데이트·복구 정책.
7. **모바일 출시 준비**: 실제 iOS/Android 기기 검증 후 Capacitor 도입, 네이티브 저장 대체, 접근성·성능·스토어 요구사항 검토.

경제 밸런스, 확률, 이자율, 상점 규칙은 플레이 검증과 별도 합의를 거쳐 결정한다.

현재 UI는 활동 / 내 정보 / 보관함 / 상점 / 채무로 정리했다. 장터와 수면은 활동에서 선택해 진입하며, 상점은 현재 판매 상품이 없는 빈 목록이다.

## 경제 밸런스 점검 — 2026-10-28

[현재 수치의 500회 분석과 조정 후보](design/economy/BALANCE_AUDIT.md)를 기준선으로 보관한다. 원금 증가 속도·사업 투자금 회수 구조는 제안 단계다. 후속 적용 시 한 항목씩 같은 시드/전략으로 비교한 뒤 물품별 거래 성격과 특별 매물 심화를 진행한다.

후속 플레이 피드백에서 자금 증가가 빠르다는 판단에 따라 원금 완화 대신 [판매 유동성 조정](design/economy/LIQUIDITY_TUNING.md)을 먼저 적용한다. 사업 매각은 제안 단계로 유지한다.

물품별 거래 성격의 첫 적용은 활성 7개 카테고리의 [공통 프로필](design/items/TRADE_PERSONALITIES.md)로 구현했다. 개별 상품 차이는 이 공통 규칙의 플레이 피드백을 바탕으로 확장한다.

## 내부 이동 분리 후 모바일 출시 과제 — 2026-11-11

게임의 화면 이동을 브라우저 History API에서 분리했다. 후속 Capacitor 작업에서는 Android 시스템 뒤로가기·루트 종료 정책·모달/진행 잠금 우선순위·iOS 제스처·저장/앱 생명주기를 검토한다. 아직 구현하지 않았으며 세부 종료 정책도 미확정이다. [항목별 작업 메모](design/ui/NAVIGATION.md#후속-작업-메모--아직-구현하지-않음)를 기준으로 진행한다.

## 승인 캐릭터 자산 후속 제작 — 2026-11-11

남녀 기본 PNG를 직접 적용한다. 추가 헤어·의상·색상·피부는 원본과 같은 스타일의 실제 자산을 제작해 인게임 크기에서 확인받은 뒤 제공한다. 기존 선택값은 보존하며 준비되지 않은 조작은 비활성 상태로 둔다. 팔/다리 동작 프레임과 인물별 외형도 같은 검토 절차로 제작한다. [자산 기준](design/character/PIXEL_CHARACTER.md)을 따른다.

## 캐릭터 방향 원복 — 2026-11-12

사용자 요청으로 B 캐릭터·PNG 방향을 보류하고 기존 24×32 도트와 전체 꾸미기를 복원했다. 위의 B 옵션별 자산 제작은 현재 진행 과제가 아니다. 이후 외형 개편은 실제 게임 크기에서 보이는 시안을 먼저 확인받고 진행한다.

## 메인/3슬롯과 웹 중심 구성 — 2026-11-12

웹 메인 메뉴와 3개 슬롯 관리·공유 설정을 개편한다. 이후 네이티브 도입 시 앱에는 OS 이벤트 수신·기기 API만 두고 웹에 백그라운드/복귀/뒤로 이벤트를 전달하는 브리지를 연결한다. 저장 완료 응답·입력 잠금·루트 종료 정책·실기기 복귀 검증은 별도 작업이다. [역할별 상세](design/ui/NAVIGATION.md#웹앱-역할-확정--2026-11-12).
