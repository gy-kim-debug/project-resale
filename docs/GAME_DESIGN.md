# 게임 설계서 — 사용자 결정 기록

작성 방식: 사용자가 처음부터 순서대로 결정한다. 개발 파트너는 매번 한 주제의 후보와 차이를 제시하고, 사용자가 선택하거나 직접 제시한 내용만 아래에 기록한다.

이전 문서의 규칙과 목업 화면의 값은 자동으로 이어받지 않는다. [이전 초안](GAME_DESIGN_REFERENCE.md)은 참고용이다. 새 결정에 따른 게임 구현은 별도 작업이며, 현재는 문서를 작성한다.

## 1. 게임 시작 상황

**확정: 완전 무일푼으로 시작한다.**

- 시작 현금: 0원.
- 시작 보유 물품: 없음.
- 첫 돈을 만드는 과정부터 플레이한다.

선택 근거: 사용자가 시작 상황 후보 1번 ‘완전 무일푼’을 선택했다.

## 2. 첫 돈을 마련하는 방법

**확정: 다음 세 가지 방법을 제공한다.**

- 무료 나눔
- 아르바이트
- 물건 수집

선택 근거: 사용자가 세 가지 방법을 직접 지정했다.

## 3. 아르바이트 보상 방식

**확정: 확정 보상형으로 진행한다.**

- 정해진 시간을 쓰면 표시된 돈을 받는다.

선택 근거: 사용자가 아르바이트 진행 방식 후보 1번 ‘확정 보상형’을 선택했다.

## 4. 아르바이트 선택 방식

**확정: 고정 일거리 여러 개 중에서 선택한다.**

- 일거리마다 소요 시간과 보수가 다르다.
- 플레이어가 원하는 일거리를 선택한다.

선택 근거: 사용자가 아르바이트 선택 방식 후보 2번 ‘고정 일거리 여러 개’를 선택했다.

## 5. 아르바이트 반복 조건

**확정: 체력·배고픔 등 상태가 허용하면 같은 일거리도 연속으로 선택할 수 있다.**

- 별도의 하루 횟수 제한 대신 상태 조건으로 수행 가능 여부를 판단한다.
- 구체적으로 어떤 상태를 확인하고 어느 수치에서 제한하는지는 아직 정하지 않았다.

선택 근거: 사용자가 체력·배고픔 등이 가능하다면 연속 선택할 수 있다고 지정했다.

## 6. 체력과 배고픔의 역할

**확정: 체력은 생명력, 배고픔은 활동 가능 여부를 제한하는 지표로 사용한다.**

- 체력: 다치거나 무리하면 감소하며, 0이 되면 사망한다.
- 배고픔: 활동 에너지 역할을 맡으며, 상태에 따라 행동을 제한한다.
- 배고픔의 회복 방법과 구체적인 변화량은 아직 정하지 않았다. 행동 제한 방식은 8절을 따른다.

선택 근거: 사용자가 체력은 후보 2번 ‘생명력’, 배고픔은 후보 1번 ‘활동 에너지’ 역할로 지정했다.

## 7. 배고픔 수치의 표시 방향

**확정: 포만도 방식으로 표시한다.**

- 수치가 높을수록 배부른 상태다.
- 활동하면 수치가 줄어든다.
- 수치가 부족하면 행동이 제한된다.

선택 근거: 사용자가 배고픔 수치 표시 방향 후보 1번 ‘포만도 방식’을 선택했다.

수치 범위, 초기값, 활동별 소모량과 회복 방법은 아직 정하지 않았다. 화면에서 사용할 지표 이름도 별도로 결정한다.

## 8. 포만도 부족 시 행동 처리

**확정: 활동에 필요한 포만도가 부족하면 해당 행동을 실행할 수 없다.**

- 부족한 포만도를 체력 소모로 대신하여 강행하는 방식은 사용하지 않는다.
- 식사 등 회복 행동의 예외와 무자금 상태의 회복 경로는 아직 정하지 않았다.

선택 근거: 사용자가 포만도 부족 시 처리 후보 중 ‘행동 불가’를 선택했다.

## 9. 수치가 0일 때의 처리 — 사용자 제안 검토 중

사용자가 다음 구조를 제안하고 검토를 요청했다. 체력 0 사망은 기존 확정 규칙이며, 아래 제안의 나머지 세부 내용은 아직 확정하지 않는다.

| 지표   | 사용자 제안                                 |
| ------ | ------------------------------------------- |
| 포만도 | 0이면 행동 불가. 채워야 행동 가능           |
| 체력   | 0이면 사망                                  |
| 피로도 | 0이면 해당 날짜 종료, 다음 날 아침으로 이동 |

### 검토할 쟁점 (개발 파트너 의견, 규칙 아님)

- 포만도 0에서 식사까지 막으면 회복할 수 없다. 제한 대상 행동과 회복 행동을 구분해야 한다.
- 현금·음식·포만도가 모두 0일 때 거래·일·수집이 막히면 진행이 멈춘다. 무료 회복 경로를 둘지, 다른 처리 방식을 쓸지 결정해야 한다. 0보다 높아도 모든 수익 활동의 필요 포만도에 못 미치는 경우를 함께 검토한다.
- ‘피로도’가 소모되어 0에서 쉬는 구조라면 남은 활동 여력을 나타내는 지표다. 유지할 이름과 수치 방향을 결정해야 한다.
- 다음 날 아침 이동 시 기준 시각, 회복 수치, 잠자리·비용, 포만도 변화, 체력 회복 여부, 채무·판매 대기·이벤트의 시간 처리를 정해야 한다. 무료 완전 회복은 가정하지 않는다.
- 한 행동으로 여러 수치가 동시에 0이 되는 경우의 판정 순서와 행동 보상 지급 시점을 결정해야 한다. 자동 날짜 이동으로 체력 0 사망이 무효화되지 않게 검토한다.

## 아직 정하지 않은 내용

무료 나눔과 물건 수집의 진행 방식·보상, 아르바이트의 구체적인 일거리 목록·보수·소요 시간, 각 방법의 비용·위험·구체적인 상태 조건은 아직 정하지 않았다. 체력의 초기값·회복·감소 조건과 변화량, 포만도 방식 지표의 범위·초기값·회복·변화량·행동 제한 기준, 그 밖의 생존 지표 구성은 미정이다. 아르바이트가 선택됐다는 이유로 별도의 직업 상태나 성장 시스템을 추가하지 않는다. 나머지 세부 규칙은 다음 논의에서 결정하며, 후보를 제시했다는 이유만으로 규칙에 포함하지 않는다.
